# 备份与同步契约

## 1. 状态与范围

- 状态：本地导出边界预留；云备份和多设备同步均为未来能力。
- 使用方：客户端本地数据/媒体服务、未来备份与同步服务。
- 权威内容：可版本化备份包、完整性、恢复安全和未来同步冲突原则。
- 不定义：上传 API、对象存储布局、加密算法、分片协议或腾讯云资源。

## 2. 备份清单

可交换的备份包必须包含：

- 产品版本和备份 schema 版本。
- 创建时间、实体或数据表版本。
- 文件清单、大小和校验值。
- 使用加密时所需的非秘密算法与版本信息。
- 用户选择包含或排除的内容说明。

备份不能包含 API Key、临时缓存、广告 SDK 状态或无需离线恢复且可重新下载的公共资源。

## 3. 恢复安全

- 恢复前验证版本、完整性、可用空间和内容范围。
- 覆盖恢复必须明确告知，并建议先导出当前数据。
- 数据和媒体应通过事务、临时数据库或等价机制完成整体校验；失败不能破坏当前可用数据。
- 版本过新时要求升级客户端，不能猜测性降级 schema。

## 4. 云端与多设备原则

- 本地数据库仍是离线可读来源，云端不可成为核心浏览和编辑的唯一来源。
- 增量同步需要稳定实体与子实体 ID；删除使用带保留期的墓碑。
- 较旧云端状态不能静默覆盖用户已确认的较新内容。
- 无法安全自动合并时保留两个版本并请求用户选择。
- 上传、分片和重试操作必须有幂等或完整性校验边界。

个性化配置的独立同步使用 `PERSONALIZATION_SYNC_CONTRACT.md`，不等待完整菜谱同步落地。

## 5. 隐私与删除

- 云备份需要账号和用户明确授权。
- 日志不记录菜谱正文或图片内容。
- 用户能够删除云端备份；账号删除流程必须明确备份和同步数据的删除规则。
- 第三方平台受限原始内容只有在授权允许时才能进入云备份。
