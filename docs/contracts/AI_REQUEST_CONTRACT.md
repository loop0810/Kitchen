# AI 请求契约

## 1. 状态与范围

- 状态：未来能力，非当前 MVP；服务端接口尚未实现。
- 使用方：客户端 AI Adapter、未来 AI 编排服务和权益服务。
- 权威内容：AI 任务的请求身份、版本、结果、重试和额度一致性语义。
- 不定义：模型供应商、HTTP 路径、JSON 字段大小写、价格或具体输出 schema。

## 2. 请求语义

每个云端 AI 任务必须携带：

- 客户端生成且重试时保持不变的幂等请求 ID。
- 任务类型。
- 完成任务所需的最小输入。
- 期望输出 schema 版本。
- 客户端能力版本。
- 用户已完成本次云端上传授权的状态。
- 采用可消耗额度时的额度预留凭证。

相同账号、任务类型和幂等请求 ID 的重复提交不能重复调用付费模型或重复扣减额度。

## 3. 响应与查询语义

服务端响应至少表达：

- 与请求一致的请求 ID。
- 实际输出 schema 版本。
- 完整或可编辑的部分结构化结果。
- 字段来源或推断标记。
- 当前任务状态及是否可安全重试。
- 额度预留、结算、释放或退款结果。

网络超时导致结果未知时，客户端必须按请求 ID 查询原任务，不能直接创建新的付费请求。

## 4. 结果边界

- AI 输出始终是 Draft，不是正式 Recipe。
- 服务端结果不能覆盖用户已经确认或修改的内容。
- 食材保留原始数量文本；推断内容单独标记；不确定信息允许为空。
- 服务端不能编造来源、作者或精确数量。
- schema 不兼容时返回明确状态，不把无法解码的结果伪装成成功。

## 5. 隐私与失败

- 未取得明确授权时不能上传图片或文字。
- 日志使用请求 ID，不记录完整菜谱正文或图片内容。
- 请求失败、超时、取消和额度不足必须可区分；具体错误 envelope 在首个服务端 API change 中确定。
- 用户拒绝云端、服务不可用或无额度时，客户端仍可使用本地解析或手动流程。
