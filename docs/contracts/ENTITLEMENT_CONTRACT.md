# 权益与额度契约

## 1. 状态与范围

- 状态：未来商业化能力，非当前 MVP；服务端账本尚未实现。
- 使用方：客户端权益缓存、未来权益服务、AI 编排和模板购买验证。
- 权威内容：权益类型、账本状态、幂等和服务端权威边界。
- 不定义：定价、订阅周期、商品 ID、平台回执格式和具体 API 路径。

## 2. 权益类型

`TemplateEntitlement` 表示模板所有权，通常不消耗；`AiCredit` 表示可消耗的 AI 使用额度。两者不能共用一个余额字段或状态机。

- 客户端缓存只用于显示和已验证权益的离线宽限，不能改变服务端权威状态。
- 没有账号和服务端映射时，不承诺 iOS 与 Android 跨平台恢复。
- 免费模板不需要购买权益；付费模板的购买、退款、撤销和恢复由服务端验证后的状态决定。

## 3. AI 额度账本

允许的核心状态流：

```text
requested → reserved → consumed
                    ↘ released
consumed           → refunded
```

- 每次预留、结算、释放、退款或发放都必须具有幂等键和可审计记录。
- 相同幂等操作不能重复扣减、退款或发放。
- 确定未执行的 AI 请求必须释放预留；已经结算后需要补偿的请求进入 refunded，而不是删除历史。
- 客户端超时后查询原操作结果；结果未知时不能自行增加余额或重复扣减。

## 4. 权威与降级

- 服务端维护用户、设备、每日和全局预算限制。
- 服务端不可用时客户端可以显示缓存，但不能创建新额度或新模板所有权。
- 零额度、权益不足或验证处理中不能阻断本地核心菜谱功能。
- AI 请求正文不属于权益账本；账本通过请求 ID 或 reservation ID 关联。

具体错误 envelope、货币规则和平台购买验证在商业化 OpenSpec change 中确定。
