# 个性化食谱配置同步契约

## 1. 状态与范围

- 状态：客户端端口和离线策略已实现；服务端 HTTP 接口尚未实现。
- 使用方：Flutter 个性化配置缓存、未来账号配置服务。
- 权威内容：共享配置快照、修订号和同步方向语义。
- 不定义：HTTP 路径、JSON 大小写、鉴权方式、FastAPI 类型和 Drift 表结构。

## 2. 共享配置快照

客户端缓存必须绑定本地命名空间：未登录使用稳定的 `device:anonymous`，登录后使用
`account:<userId>`。命名空间只用于隔离账号配置缓存，不代表菜谱、集合、导入任务或
媒体获得了账号 owner。

账号配置快照包含：

- `categories`：有序主分类选项；至少保留一个有效选项。
- `tags`：有序标签选项；允许为空。
- `difficulties`：有序难度选项；至少保留一个有效选项，首项为无法解析时的默认难度。
- `serverRevision`：服务端生成的不透明修订号；尚未成功同步时允许为空。

旧版无法判断归属的单例缓存迁移到 `device:anonymous`，不得在首次登录时自动上传。

列表顺序属于契约语义。客户端可以去除首尾空白、空项和重复项，但不能自行重排服务端确认后的快照。

`syncPending`、`lastSyncedAt` 和客户端缓存更新时间属于客户端同步元数据，不进入服务端账号配置快照。

## 3. 远端操作语义

- `fetch` 返回当前账号的完整配置快照；账号尚无配置时返回服务端默认快照。
- `update` 接收客户端完整配置意图，并返回服务端确认后的完整快照和修订号。
- 同一更新意图的重试必须幂等，不能生成重复选项或额外副作用。
- 客户端不能自行生成或递增 `serverRevision`，只能保存服务端返回值。

远端网关必须从 `AUTH_CONTRACT.md` 定义的正式会话解析当前账号，不接受客户端自行传入的 `userId` 或 owner 字段。稳定选项 ID、并发修订冲突、幂等键和错误响应格式必须遵循对应正式 API 契约；不能把当前显示文字默认当作长期网络 ID。

## 4. 客户端同步方向

```text
本地无 pending → fetch → 原子替换缓存
本地有 pending → update → 服务端确认后原子替换缓存并清除 pending
```

- 本地编辑必须先持久化并标记 pending，再尝试远端更新。
- 同步实现必须捕获发起操作时的命名空间；响应提交前不得把结果写入另一个命名空间。
- 请求失败或结果未知时保留本地快照和 pending，不能伪报同步成功。
- 没有远端适配器、未登录或网络不可用时，本地创建、导入和编辑继续工作。
- 服务端返回的新快照只有在完整校验成功后才能替换当前缓存。
