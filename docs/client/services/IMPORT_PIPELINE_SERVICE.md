# 导入处理服务需求

## 1. 定位

导入处理服务负责从接收外部输入到生成可确认菜谱草稿的完整任务状态机。它
协调媒体、结构化 OCR、本地布局分析和保守规则解析，但不直接决定用户最终保存的
菜谱内容。未来付费 AI 是用户主动选择的独立增强阶段，不属于默认导入流水线。

## 2. 输入

- 第三方应用分享链接。
- 分享文案。
- 纯文字。
- 单张图片。
- 多张连续截图。
- 应用内粘贴。

MVP 不直接接收完整视频文件。

## 3. 首要规则

任何处理前先创建本地 ImportTask：

```text
接收到输入
→ 本地持久化成功
→ 才开始解析
```

接收成功但解析失败时，用户输入仍必须存在于导入箱。

## 4. 状态机

```text
等待处理
→ 正在提取
→ 正在识别图片
→ 正在整理菜谱
→ 等待确认
→ 已保存

任意处理中状态
→ 处理失败
→ 重试 / 手动补充 / 放弃

等待或处理中状态可以由用户取消；取消后保留任务，直到用户明确删除。
```

状态必须可持久化并在应用重启后恢复。

## 5. 处理阶段

1. 标准化输入类型和来源。
2. 保存原文、链接和媒体引用。
3. 提取公开可访问内容。
4. 对图片执行方向、顺序和可读性检查。
5. 调用 OCR，并保留页码、文本行、归一化坐标和可用的识别置信度。
6. 按几何位置恢复阅读顺序，过滤跨页重复的页眉、页脚和平台界面文字。
7. 使用通用菜谱语义解析候选标题、食材和步骤，不为具体平台或截图模板写规则。
8. 为候选字段记录原文证据、来源页和本地置信等级。
9. 进行结构校验；不能可靠分类的文字保留在 OCR 原文，不强行写入菜谱字段。
10. 生成用户确认草稿。

每张图片具有稳定媒体 ID、用户顺序、忽略状态、内容修订号和独立 OCR 状态。
任务另外维护单调递增的处理代次；图片在识别期间被替换、裁剪、旋转或重排时，
旧代次结果不得回写当前任务。

## 6. 任务控制

- 支持取消尚未进入不可中断阶段的任务。
- 支持失败重试。
- 重试使用同一个任务 ID，不重复扣费。
- 同一原始输入允许用户主动创建新任务。
- 后台能力受平台限制时，前台恢复后继续。
- 任务进度使用业务阶段，不展示虚假百分比。
- 所有状态允许用户确认后删除。处理中任务先标记取消再删除；OCR、提取或结构化
  阶段观察到记录已删除时安全终止，不继续写入或回写失败。
- 删除数据库记录后清理 `import_media` 受控文件；不得触碰受控目录外路径，清理
  失败留给启动期孤立文件清理。

## 7. 媒体管理与增量重处理

- 用户可以在同一任务中追加、替换、重排、裁剪、按 90 度旋转、忽略和恢复图片。
- 原图和当前有效处理图都位于应用受控目录；操作外部相册或分享 URI 前必须先复制。
- 内容改变只使目标页 OCR 失效；未改变且已成功的页面继续复用。
- 单纯重排只重新汇总阅读顺序和结构化草稿，不重复 OCR 页面。
- 编辑 OCR 正文或补充说明只重新执行结构化阶段。
- 所有图片均被忽略时停止处理，并提供恢复、替换、追加或手动创建入口。
- 媒体变更与数据库引用切换使用原子操作；文件写入失败时不得留下指向无效文件的
  数据库记录。

## 8. 图片降级

OCR 不足时允许：

- 重新选择图片。
- 调整顺序。
- 裁剪或旋转。
- 修改 OCR 文字。
- 输入自然语言补充。
- 手动增加食材和步骤。
- 忽略某张图片。
- 保存为待完善菜谱。

OCR 结果按页保存 `pending / processing / succeeded / failed` 状态。多图中单页失败
不能清除其他成功页；用户可以只重试、替换或忽略失败页，也可以使用成功页继续
生成不完整草稿。所有页面失败时仍保留任务、图片、校对文字和补充说明。

## 9. 用户文字与确认草稿

机器 OCR 汇总、用户校对正文和用户自然语言补充分别保存：

- 重新 OCR 可以更新机器汇总，不覆盖用户校对或补充。
- 用户可以明确选择以最新机器结果重新开始校对，该操作需要确认。
- 确认页按问题摘要、基础信息、食材、准备工作、步骤、分类标签和来源分区。
- 自动字段展示来源、离散可信等级和可用证据；没有证据时保持为空或待补充。
- 用户编辑或确认字段具有最高优先级；重新处理产生冲突时保留用户值并展示候选。
- 用户编辑或排序过的食材、步骤列表在当前版本按整个列表保护。
- 确认进度自动持久化，退出后可以继续；缺少食材或步骤时允许保存为待完善菜谱。

## 10. 来源和可信度

每个结构化字段至少区分：

- 来源明确提供。
- 本地推断或未来 AI 推断。
- 用户编辑。
- 用户确认。

低可信内容使用温和提示，不使用难以解释的精确百分比。

本地解析采用保守策略：缺少明确菜名、食材或步骤时允许字段为空，并把任务标记为
“需要确认”或“信息不完整”。不得为了提高字段填充率，把做法文字猜成食材，或把
平台按钮、作者信息和推荐内容保存进菜谱。

## 11. 平台边界

- iOS Share Extension 与 Android Share Intent 只负责安全接收和持久化。
- Android 分享先把文字元数据和媒体复制到应用私有暂存区，并原子写入版本化清单；
  主应用确认 ImportTask 已落库后才删除清单。
- 重型 OCR 处理在主应用或允许的后台能力中执行。
- 不要求分享操作强制打开主应用。
- 不绕过第三方平台验证、反爬或版权保护。
- 公开链接只接受 HTTPS，并拒绝本机、私网、非 HTML、超过 2 MB 或重定向
  超过 3 次的响应；单次读取超时为 10 秒。
- 原文中的 HTTP 链接只允许在本地把 scheme 升级为 HTTPS 后尝试，不发送明文
  HTTP 请求；目标不支持 HTTPS 时保留原文并按不可访问降级。

## 12. 错误

至少区分：

- 输入不支持。
- 原始内容无法保存。
- 链接不可访问。
- 图片不可读。
- OCR 失败。
- 端侧能力不可用。
- 草稿结构无效。

每种错误提供下一步动作，而不是只显示“失败”。

## 13. 验收

- 无网络时可以接收并保存输入。
- 应用被终止后任务和原始输入仍存在。
- 任意解析失败不会丢失 OCR 或手动结果。
- 多图中单页失败时保留成功页，并可只重试、替换或忽略失败页。
- 用户调整顺序后按新顺序整理，旋转或替换单页不重复识别其他成功页。
- 处理期间修改媒体时，旧处理代次不能覆盖当前图片或草稿。
- 重新识别和重新整理不会覆盖用户编辑或确认字段。
- 退出确认页再返回时恢复字段、顺序、来源和确认状态。
- 拼接图、无食材清单和多栏截图不会因为字段不足而被强行补全。
- 用户不使用 AI 也能完全离线完成导入、校对和确认。
- 未来付费 AI 未经用户明确选择和授权，不上传图片或 OCR 正文。
