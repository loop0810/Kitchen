# AI 编排服务需求

## 1. 定位

AI 编排服务是未来的付费增强服务。它在用户主动选择、完成权益校验并授权上传后，
根据任务类型和质量选择模型，将结果合并为可解释的菜谱草稿。

它不属于当前 MVP 或默认导入流水线，不直接修改正式菜谱，也不允许 Widget 直接
调用模型供应商。具体定价形态另行确认。

AI 请求身份、版本、幂等、结果查询和额度一致性的跨端权威定义见
`../../contracts/AI_REQUEST_CONTRACT.md`。本文只保留客户端编排、降级和草稿确认边界，
不定义 HTTP 字段或服务端内部实现。

## 2. 处理层级

```text
本地 OCR 与保守解析结果
→ 用户主动选择 AI 辅助
→ 权益和上传授权确认
→ 付费 AI
→ 结构校验
→ 用户确认
```

前一层结果可以作为后一层输入，不能因为调用更强模型就覆盖用户已经修改的内容。

## 3. 职责

- 评估任务需要的能力。
- 检查模型可用性。
- 请求和结算付费权益或额度。
- 调用抽象的模型 Adapter。
- 统一结构化输出。
- 记录字段来源和推断状态。
- 验证必要字段、类型和顺序。
- 提供失败原因和降级建议。
- 控制超时、取消和有限重试。

## 4. 非职责

- 不持有生产 API Key。
- 不直接展示广告。
- 不决定正式菜谱最终内容。
- 不上传未经用户授权的图片或文字。
- 不在日志中记录完整菜谱正文。

## 5. 能力选择

选择依据：

- 输入类型和长度。
- 是否包含图片。
- 本地 OCR 和解析已提供的信息。
- 网络状态。
- 用户是否允许云端处理。
- 当前付费权益或 AI Credit。
- 服务端预算和全局限流。
- 前序结果是否已满足质量门槛。

AI 不是默认必经步骤，也不能因本地结果低可信而自动触发。

## 6. 请求协议

跨端请求和响应语义由 `../../contracts/AI_REQUEST_CONTRACT.md` 唯一定义。客户端 Adapter
负责生成并在重试时复用请求 ID、声明自身能力、校验响应 schema，并把网络状态转换为
领域可理解的成功、处理中、可重试、不可重试或结果未知状态。

## 7. 额度一致性

额度状态机由 `../../contracts/ENTITLEMENT_CONTRACT.md` 定义。客户端不能自行增加余额；
网络超时但服务端结果未知时，通过原请求 ID 查询，不创建新的付费任务。

## 8. 输出要求

- 输出是 Draft，不是正式 Recipe。
- 食材保留原始数量文本。
- 推断内容单独标记。
- 不确定信息允许为空。
- 不编造来源、作者或精确数量。
- 步骤顺序和食材引用通过结构校验。
- 无法满足 schema 时返回可编辑的部分结果。

## 9. 隐私

- 首次云端上传前明确告知输入类型和用途。
- 只上传完成任务所需的数据。
- 服务端保存期限应可说明。
- 用户可以拒绝云端并继续本地或手动流程。
- 日志使用请求 ID，不记录完整正文。

## 10. 测试

- 规则解析单元测试。
- AI 服务不可用降级测试。
- 无额度降级测试。
- 云端超时和幂等测试。
- 成功、失败和退款一致性测试。
- schema 不兼容测试。
- 用户编辑内容不被覆盖测试。

## 11. 验收

- 无网络和无付费权益时仍能生成本地结果或进入手动确认。
- Widget 不包含模型供应商调用。
- 客户端安装包不包含生产服务密钥。
- 相同幂等请求不会重复扣费。
- 云端故障具有明确退款或查询路径。
