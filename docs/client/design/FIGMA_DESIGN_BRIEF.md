## 2. 本轮设计目标

本轮只验证一个完整视觉切片：

```text
菜谱库
→ 单击手账
→ 菜谱详情

菜谱库
→ 菜谱集
→ 翻阅菜谱集
→ 手账阅读器
→ 单击手账
→ 菜谱详情
```

需要回答：

1. 竖屏软木板是否适合长时间浏览。
2. 双列手账缩略图是否能兼顾数量和辨识度。
3. 同一模板缩小和全屏展示时是否保持一致。
4. 手账感是否足够，但不会显得幼稚、杂乱或只面向女性。
5. 手账页与完整菜谱详情是否有清晰职责区分。
6. 视觉组件是否可以在 Flutter 中稳定复用。

## 4. 用户与品牌感受

### 4.1 核心用户

- 喜欢整理、记录和生活感。
- 经常从多个平台收藏做饭内容。
- 希望菜谱不只是工具，也能形成个人积累。
- 主要早期用户为女性，但设计必须保持包容。

### 4.2 期望感受

- 温暖。
- 生活化。
- 手作感。
- 轻松但不幼稚。
- 有个人收藏册的归属感。
- 内容可靠且容易再次找到。

### 4.3 避免

- 过度粉色或性别化。
- 儿童贴纸书风格。
- 高饱和、过多彩虹色。
- 所有元素都倾斜或不对齐。
- 纸张纹理过重。
- 低对比度正文。
- 把 Material Card 简单换成米色背景。
- 贴纸覆盖菜名和食材。

## 5. 视觉方向

### 5.1 核心隐喻

菜谱库是一块竖向的个人软木板；每道菜是一张被图钉、胶带或活页孔固定的
手账纸。菜谱集像一本整理好的活页菜谱册，阅读器用于翻阅该册。

### 5.2 视觉层次

从后到前：

```text
低对比度背景
→ 纸张阴影
→ 手账纸
→ 数据色块
→ 菜名和主要食材
→ 少量胶带、贴纸和图钉
→ 收藏、待完善等交互状态
```

### 5.3 控制原则

- 每张手账最多使用 2 种主要装饰。
- 每张手账最多使用 3 种强调色。
- 倾斜角度控制在 -1.2° 到 1.2°。
- 手账纸边缘可以有轻微不规则感，但命中区域保持规则。
- 纸张阴影轻于常规浮层阴影。
- 纹理只产生材质感，不影响文字识别。

## 7. 字体与文字

### 7.1 UI 与正文

使用系统中文字体：

- PingFang SC。
- Noto Sans CJK SC。
- Microsoft YaHei 作为平台回退。

### 7.2 手写字体

- 只用于菜名、编号或不超过 8 个汉字的短标签。
- 本轮允许使用“手写标题体”占位样式。
- 正式字体必须在开发前确认商业授权和安装包体积。
- 食材、数量、按钮和详细步骤使用系统字体。

### 7.3 基础字号

| 样式 | 建议字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| Page Title | 22 | 700 | 页面标题 |

| Thumbnail Title | 15～17 | 700 | 缩略图菜名 |
| Body | 16 | 400 | 详情正文 |

## 8. 间距、圆角与阴影

### 8.1 间距

优先复用现有间距：

```text
4, 8, 12, 16, 20, 24, 28, 32
```

### 8.2 圆角

- 搜索框：28。
- 主要按钮：16。
- 普通信息容器：14～18。
- 手账纸：4～10，避免过度卡片化。
- 贴纸和标签根据造型独立定义。

### 8.3 阴影

手账纸建议：

```text
X: 0
Y: 3
Blur: 10
Spread: 0
Color: #5A3E2B / 12%
```

阅读器大纸张可以使用：

```text
X: 0
Y: 8
Blur: 24
Color: #5A3E2B / 16%
```

避免多层深色 Material 阴影。

## 9. 页面一：菜谱库

### 9.1 页面目标

让用户快速浏览自己的手账菜谱、搜索、筛选、进入详情和访问菜谱集。

### 9.2 固定结构

```text
状态栏
页面标题“我的菜谱” + 创建按钮
搜索框“搜索我的菜谱”
快速筛选：全部 / 收藏 / 做过 / 待完善
菜谱与菜谱集入口
双列手账缩略图
四栏底部导航
```

### 9.3 软木板

- 只应用于菜谱内容滚动区，避免覆盖系统状态栏和底部导航。
- 顶部搜索和筛选区域使用 Paper 背景，保证操作清晰。
- 内容区与工具区之间可以使用撕纸边缘或简单分隔，不使用重阴影。
- 双列横向间距 12～16。
- 内容区左右安全边距 16。
- 第一屏至少看到 3 张完整或部分手账，避免一屏只有一张。

### 9.4 手账缩略图

- 比例约 2:3。
- 同一模板等比缩小。
- 菜名必须可辨识。
- 主要食材文字允许作为视觉摘要，不要求在缩略尺寸完全阅读。
- 收藏按钮必须有独立命中区。
- 待完善使用标签和图标，不只使用颜色。
- 装饰不得阻挡收藏按钮。

### 9.5 点击行为

- 点击手账主体：直接进入菜谱详情。
- 点击收藏：只切换收藏。
- 长按：未来进入多选，本轮只预留状态。
- 点击创建：进入现有创建流程，本轮不设计后续页。

## 10. 菜谱集入口探索

菜谱集入口尚未锁定视觉结构，需要 Figma 输出两个低保真方案。

### 10.1 方案 A：分段切换，推荐优先探索

```text
[ 菜谱 ] [ 菜谱集 ]
```

优点：

- 信息结构清晰。
- 菜谱和菜谱集不会同时争夺首屏空间。
- 未来容易增加集合管理。

风险：

- 用户可能忽略第二个分段。
- 从菜谱到集合需要一次切换。

### 10.2 方案 B：顶部菜谱集横向条

```text
我的菜谱集  [家常菜] [烘焙] [早餐] [全部 >]
```

优点：

- 菜谱集更容易被发现。
- 页面更像真实收藏板。

风险：

- 搜索、筛选、集合和内容同时出现，顶部可能拥挤。
- 小屏首屏有效内容减少。

### 10.3 评审标准

- 用户是否容易发现“翻阅菜谱集”。
- 首页是否过于拥挤。
- 菜谱缩略图首屏数量。
- 菜谱集未来管理能力是否容易扩展。

本轮不把任何一个方案视为已确认产品决策。

## 11. 页面二：菜谱集管理

### 11.1 页面目标

查看和维护菜谱集成员；空集合从书封点击进入后在此完成添加。

### 11.2 结构

```text
返回
返回 + 菜谱集名称
添加菜谱
集合成员列表
侧滑移除
长按拖动排序
```

### 11.3 交互

- 点击成员手账：直接进入菜谱详情。
- 空集合：展示“先添加菜谱”及明确添加按钮。
- 非空集合从菜谱库书封直接进入阅读器，不在管理页重复提供翻阅主按钮。

### 11.4 视觉

- 成员列表保持与手账缩略图和活页纸体系一致。
- 添加、移除和拖动入口需满足大点击区域与明确语义标签。

## 12. 页面三：手账阅读器

### 12.1 页面目标

沉浸翻阅当前菜谱集中的手账摘要。

### 12.2 结构

```text
返回 + 菜谱集名称
首字母分组或当前菜名
居中的完整手账纸
页码，例如 3 / 12
左右滑动提示，首次出现
```

主导航在阅读器中隐藏。
阅读器不展示编辑、成员管理或更多操作按钮。

### 12.3 内容

每页只显示：

- 一道菜名。
- 最多 4 项主要食材。
- 每项主要食材数量。
- 模板装饰。
- “查看详细步骤”视觉入口。
- 待完善状态，适用时。

不显示：

- 全部食材。
- 详细步骤。
- 来源全文。
- 广告。

### 12.4 交互

- 左右滑动切换当前菜谱集成员。
- 不循环。
- 到首尾使用系统回弹。
- 点击手账主体或“查看详细步骤”：进入同一菜谱详情。
- 从详情返回：保持原页码。

### 12.5 动效

MVP 只设计：

- 水平滑动。
- 当前页轻微缩放。
- 页面阴影变化。
- 相邻页面露出 4%～8%，可选。

不设计真实卷页 Shader。

## 13. 页面四：菜谱详情

### 13.1 页面目标

高效查看完整内容，并在需要时进入编辑。

### 13.2 内容顺序

1. 封面、菜名和简介。
2. 份量、准备时间、烹饪时间和难度。
3. 分类和标签。
4. 食材和数量。
5. 准备工作。
6. 全部步骤。
7. 长期笔记。
8. 来源。

### 13.3 视觉

- 使用 Paper 背景和少量手账分割元素。
- 详细正文不放入固定手账模板。
- 食材和步骤使用系统字体。
- 手账风格可以使用胶带式标题、波浪分割线或小贴纸。
- 不让每个区块都变成独立圆角 Card。

### 13.4 交互

- 返回来源页面。
- 收藏。
- 编辑。
- 更换模板。
- 加入菜谱集。

## 14. 首套免费手账模板

### 14.1 模板定位

名称暂定：`暖日厨房 / Warm Kitchen 01`

特点：

- 暖白活页纸。
- 珊瑚红标题。
- 黄油黄胶带。
- 鼠尾草绿小标签。
- 少量雾蓝圆点。
- 一个厨房主题小贴纸。
- 不依赖成品图。

### 14.2 设计画布

```text
Width: 1000
Height: 1500
Aspect Ratio: 2:3
Safe Area: 80
```

所有坐标以设计画布为基准，Flutter 后续转换为归一化位置。

### 14.3 槽位提案

| 槽位 | X | Y | W | H | 规则 |
| --- | ---: | ---: | ---: | ---: | --- |
| 菜名 | 120 | 150 | 760 | 170 | 最多 2 行，标题优先 |
| 分类标签 | 120 | 340 | 260 | 70 | 可隐藏 |
| 时间标签 | 620 | 340 | 260 | 70 | 可隐藏 |
| 食材 1 | 150 | 500 | 700 | 120 | 名称左、数量右 |
| 食材 2 | 150 | 640 | 700 | 120 | 名称左、数量右 |
| 食材 3 | 150 | 780 | 700 | 120 | 名称左、数量右 |
| 食材 4 | 150 | 920 | 700 | 120 | 名称左、数量右 |
| 待完善标签 | 690 | 90 | 210 | 72 | 条件显示 |
| 详情入口 | 250 | 1280 | 500 | 100 | “查看详细步骤” |

### 14.4 装饰安全区

- 顶部胶带不得覆盖菜名槽。
- 活页孔位于左侧 24～70 区域。
- 贴纸优先位于右下角和左上角安全区。
- 详情入口周围 32 内不得有可误认为按钮的装饰。
- 食材槽背景对比度必须保证 Ink 文字可读。

### 14.5 模板状态

至少设计：

- 正常，4 项食材。
- 2 项食材。
- 无数量文本。
- 长菜名。
- 待完善。
- 英文菜名。
- 缩略模式。
- 阅读模式。

## 18. Prototype 路径

必须可点击验证：

### 路径 A

```text
菜谱库
→ 点击“番茄炒蛋”
→ 菜谱详情
→ 返回菜谱库
```

### 路径 B

```text
菜谱库
→ 菜谱集
→ 点击非空“家常菜”书封
→ 左右翻页
→ 点击“红烧牛腩”
→ 菜谱详情
→ 返回原阅读页
```

### 路径 C

```text
空菜谱集
→ 点击书封
→ 进入成员管理并显示添加菜谱引导
```

## 19. 响应式与无障碍

- 基准设计宽度 390。
- 额外验证 360 和 430 宽度。
- 验证系统文字 1.0、1.3 和 1.5 倍。
- 1.3 倍以上菜谱库允许单列。
- 手账装饰元素不需要焦点或朗读。
- 手账主体语义需要包含菜名、主要食材和状态。
- 收藏按钮需要独立标签。
- 所有正文与背景达到可读对比。
- 不能只靠珊瑚红表示收藏或待完善。

## 20. Flutter 可实现性约束

- 页面结构使用 Auto Layout，避免完全自由散放。
- 手账装饰可以叠层，但业务文字槽使用固定 Frame。
- 不把完整手账连同文字导出为一张图片。
- 背景、胶带和贴纸可以导出为 SVG、PNG 或 WebP。
- 不依赖 Figma 自动生成 Flutter 代码。
- 不使用无法在 Flutter 稳定复现的复杂混合模式。
- 不使用大量高斯模糊和实时滤镜。
- 每个视觉尺寸应可映射到 Design Token 或模板定义。

## 21. 素材交付

每个素材需要说明：

- 名称。
- 用途。
- 格式。
- 原始尺寸。
- 是否可着色。
- 是否平铺。
- 是否属于免费模板。
- 授权来源。

建议：

- 矢量造型使用 SVG。
- 复杂纸张纹理使用 WebP 或 PNG。
- 纹理提供 1x 和 2x 所需源尺寸。
- 不导出带有菜谱正文的模板背景图。

## 22. 设计评审问题

第一轮设计完成后回答：

1. 菜谱库入口采用分段切换还是集合横向条。
2. 软木背景使用纯色还是轻纹理。
3. 手写字体只用于菜名，还是同时用于短标签。
4. 缩略图中主要食材需要真实可读，还是主要表达视觉身份。
5. 阅读器是否露出相邻页面。
6. “查看详细步骤”使用按钮、贴纸标签还是整页点击提示。
7. 手账纸使用活页孔、图钉还是胶带作为首套模板主要元素。
