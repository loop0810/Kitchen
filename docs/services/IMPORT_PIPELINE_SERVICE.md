# 导入处理服务需求

## 1. 定位

导入处理服务负责从接收外部输入到生成可确认菜谱草稿的完整任务状态机。它
协调媒体、OCR、本地规则和 AI 服务，但不直接决定用户最终保存的菜谱内容。

## 2. 输入

- 第三方应用分享链接。
- 分享文案。
- 纯文字。
- 单张图片。
- 多张连续截图。
- 应用内粘贴。

MVP 不直接接收完整视频文件。

## 3. 首要规则

任何处理前先创建本地 ImportTask：

```text
接收到输入
→ 本地持久化成功
→ 才开始解析
```

接收成功但解析失败时，用户输入仍必须存在于导入箱。

## 4. 状态机

```text
等待处理
→ 正在提取
→ 正在识别图片
→ 正在整理菜谱
→ 等待确认
→ 已保存

任意处理中状态
→ 处理失败
→ 重试 / 手动补充 / 放弃

等待或处理中状态可以由用户取消；取消后保留任务，直到用户明确删除。
```

状态必须可持久化并在应用重启后恢复。

## 5. 处理阶段

1. 标准化输入类型和来源。
2. 保存原文、链接和媒体引用。
3. 提取公开可访问内容。
4. 对图片执行方向、顺序和可读性检查。
5. 调用 OCR。
6. 调用本地规则解析。
7. 必要时调用端侧或云端 AI。
8. 合并候选字段并记录来源。
9. 进行结构校验。
10. 生成用户确认草稿。

## 6. 任务控制

- 支持取消尚未进入不可中断阶段的任务。
- 支持失败重试。
- 重试使用同一个任务 ID，不重复扣费。
- 同一原始输入允许用户主动创建新任务。
- 后台能力受平台限制时，前台恢复后继续。
- 任务进度使用业务阶段，不展示虚假百分比。
- 所有状态允许用户确认后删除。处理中任务先标记取消再删除；OCR、提取或结构化
  阶段观察到记录已删除时安全终止，不继续写入或回写失败。
- 删除数据库记录后清理 `import_media` 受控文件；不得触碰受控目录外路径，清理
  失败留给启动期孤立文件清理。

## 7. 图片降级

OCR 不足时允许：

- 重新选择图片。
- 调整顺序。
- 裁剪或旋转。
- 修改 OCR 文字。
- 输入自然语言补充。
- 手动增加食材和步骤。
- 忽略某张图片。
- 保存为待完善菜谱。

## 8. 来源和可信度

每个结构化字段至少区分：

- 来源明确提供。
- AI 推断。
- 用户编辑。
- 用户确认。

低可信内容使用温和提示，不使用难以解释的精确百分比。

## 9. 平台边界

- iOS Share Extension 与 Android Share Intent 只负责安全接收和持久化。
- Android 分享先把文字元数据和媒体复制到应用私有暂存区，并原子写入版本化清单；
  主应用确认 ImportTask 已落库后才删除清单。
- 重型 OCR 或 AI 处理在主应用或允许的后台能力中执行。
- 不要求分享操作强制打开主应用。
- 不绕过第三方平台验证、反爬或版权保护。
- 公开链接只接受 HTTPS，并拒绝本机、私网、非 HTML、超过 2 MB 或重定向
  超过 3 次的响应；单次读取超时为 10 秒。
- 原文中的 HTTP 链接只允许在本地把 scheme 升级为 HTTPS 后尝试，不发送明文
  HTTP 请求；目标不支持 HTTPS 时保留原文并按不可访问降级。

## 10. 错误

至少区分：

- 输入不支持。
- 原始内容无法保存。
- 链接不可访问。
- 图片不可读。
- OCR 失败。
- 端侧能力不可用。
- 云端额度不足。
- 云端服务失败。
- 草稿结构无效。

每种错误提供下一步动作，而不是只显示“失败”。

## 11. 验收

- 无网络时可以接收并保存输入。
- 应用被终止后任务和原始输入仍存在。
- 云端失败不会丢失 OCR 或手动结果。
- 重试不会重复扣除成功前已退还的额度。
- 用户可以不使用 AI，完全手动完成确认。
