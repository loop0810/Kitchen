# AI 编排服务需求

## 1. 定位

AI 编排服务根据设备能力、网络、任务类型、质量和额度选择本地规则、端侧模型
或云端模型，将结果合并为可解释的菜谱草稿。

它不直接修改正式菜谱，也不允许 Widget 直接调用模型供应商。

## 2. 处理层级

```text
端侧 OCR
→ 本地规则解析
→ 系统或端侧模型
→ 受限云端 AI
→ 结构校验
→ 用户确认
```

前一层结果可以作为后一层输入，不能因为调用更强模型就覆盖用户已经修改的内容。

## 3. 职责

- 评估任务需要的能力。
- 检查端侧能力和模型可用性。
- 请求和结算云端额度。
- 调用抽象的模型 Adapter。
- 统一结构化输出。
- 记录字段来源和推断状态。
- 验证必要字段、类型和顺序。
- 提供失败原因和降级建议。
- 控制超时、取消和有限重试。

## 4. 非职责

- 不持有生产 API Key。
- 不直接展示广告。
- 不决定正式菜谱最终内容。
- 不上传未经用户授权的图片或文字。
- 不在日志中记录完整菜谱正文。

## 5. 能力选择

选择依据：

- 输入类型和长度。
- 是否包含图片。
- 设备端 OCR 和模型支持。
- 网络状态。
- 用户是否允许云端处理。
- 当前 AI Credit。
- 服务端预算和全局限流。
- 前序结果是否已满足质量门槛。

云端 AI 不是默认必经步骤。

## 6. 请求协议

云端请求至少包含：

- 幂等请求 ID。
- 任务类型。
- 最小必要输入。
- 输出 schema 版本。
- 客户端能力版本。
- 用户授权状态。
- 额度预留凭证。

云端响应至少包含：

- 请求 ID。
- schema 版本。
- 结构化结果。
- 字段来源或推断标记。
- 可重试状态。
- 额度结算结果。

## 7. 额度一致性

推荐流程：

```text
请求额度预留
→ 获得 reservationId
→ 执行云端请求
→ 成功结算

确定未完成
→ 取消预留或退还
```

客户端不能自行增加余额。网络超时但服务端结果未知时，通过请求 ID 查询，不
立即重复调用。

## 8. 输出要求

- 输出是 Draft，不是正式 Recipe。
- 食材保留原始数量文本。
- 推断内容单独标记。
- 不确定信息允许为空。
- 不编造来源、作者或精确数量。
- 步骤顺序和食材引用通过结构校验。
- 无法满足 schema 时返回可编辑的部分结果。

## 9. 隐私

- 首次云端上传前明确告知输入类型和用途。
- 只上传完成任务所需的数据。
- 服务端保存期限应可说明。
- 用户可以拒绝云端并继续本地或手动流程。
- 日志使用请求 ID，不记录完整正文。

## 10. 测试

- 规则解析单元测试。
- 端侧不可用降级测试。
- 无额度降级测试。
- 云端超时和幂等测试。
- 成功、失败和退款一致性测试。
- schema 不兼容测试。
- 用户编辑内容不被覆盖测试。

## 11. 验收

- 无网络和无额度时仍能生成本地结果或进入手动确认。
- Widget 不包含模型供应商调用。
- 客户端安装包不包含生产服务密钥。
- 相同幂等请求不会重复扣费。
- 云端故障具有明确退款或查询路径。
