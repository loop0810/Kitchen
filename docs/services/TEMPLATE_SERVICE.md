# 手账模板服务需求

## 1. 定位

模板服务负责手账模板的注册、校验、渲染、缓存、版本兼容和权益检查。模板只
控制菜谱摘要页的表现，不保存完整菜谱内容。

当前属于菜谱核心能力；远端目录、购买和上传为后续阶段。

## 2. 服务对象

- 菜谱创建与编辑。
- 菜谱库缩略图。
- 菜谱集手账阅读器。
- 菜谱详情中的模板更换。
- 未来模板商店和模板编辑器。
- 未来导出与打印。

## 3. 职责

- 提供内置和已下载模板目录。
- 按 ID 和版本解析模板。
- 验证槽位、资源和最低版本。
- 将 Recipe 摘要映射到模板数据槽。
- 渲染缩略图和阅读器页面。
- 处理字体、图片和装饰资源。
- 检查 TemplateEntitlement。
- 缓存远端模板和兼容版本。
- 模板失败时选择默认降级模板。

## 4. 非职责

- 不保存完整食材或步骤。
- 不决定菜谱内容真假。
- 不处理应用商店支付。
- 不直接发放 AI Credit。
- 不在 Feature 中复制菜谱业务逻辑。

## 5. 模板模型

```text
TemplateDefinition
├── id
├── version
├── name
├── author
├── aspectRatio
├── previewAsset
├── backgroundAsset
├── slots[]
├── decorationLayers[]
├── bundledFonts[]
├── minimumAppVersion
└── entitlementType
```

```text
TemplateSlot
├── kind
├── rect
├── alignment
├── textStyle
├── maxLines
├── overflowRule
├── visibleInThumbnail
└── accessibilityLabel
```

## 6. 第一阶段槽位

- 菜名。
- 主要食材 1～4。
- 主要食材数量。
- 可选分类。
- 可选时间。
- 详情入口视觉位置。

手账页不展示完整步骤，因此第一阶段不需要步骤分页模板。

## 7. 渲染模式

### 7.1 缩略模式

- 用于双列菜谱库。
- 保持模板整体构图。
- 菜名优先可见。
- 装饰可以简化。
- 提供完整语义摘要。

### 7.2 阅读模式

- 用于菜谱集阅读器。
- 每屏一张手账。
- 显示主要食材和数量。
- 提供进入详情的交互区域。

两种模式使用同一模板定义，不维护两套业务数据。

## 8. 版本与兼容

- 内置模板也需要稳定 ID。
- 远端模板使用不可变版本。
- 菜谱保存 templateId，远端模板上线前增加 templateVersion。
- 模板更新不能静默破坏旧菜谱。
- 下架模板对已授权用户保留兼容资源。
- minimumAppVersion 不满足时禁止应用并说明原因。

## 9. 失败降级

- 模板不存在：使用内置默认模板。
- 资源缺失：忽略非关键装饰或使用默认资源。
- 字体缺失：使用声明的安全回退字体。
- 槽位无效：模板校验失败，不进入可选目录。
- 权益无法联网确认：已缓存有效权益按既定宽限策略处理。
- 任何模板失败都不能阻止进入完整菜谱详情。

## 10. 性能

- 设计画布等比例缩放，不按设备硬编码坐标。
- 静态装饰使用 RepaintBoundary 或等效缓存。
- 列表不重复解析模板 JSON。
- 图片按目标尺寸解码。
- 大量菜谱时允许缓存缩略图，菜谱或模板变化后失效。

## 11. 模板编辑与上传

未来编辑器编辑数据槽和装饰层，而不是直接把某道菜的文字写进模板。

公开前必须校验：

- 必要槽位。
- 可读性和安全区。
- 资源大小和格式。
- 字体和图片授权声明。
- 版本完整性。
- 违规和版权内容。

## 12. 验收

- 同一道菜在缩略和阅读模式保持模板一致。
- 切换模板不修改菜谱结构。
- 模板损坏时默认模板可用。
- 缩略列表滚动不会反复加载原始大图。
- 装饰元素不进入无障碍语义树。
- 未授权付费模板不能被应用，但可以安全预览。
