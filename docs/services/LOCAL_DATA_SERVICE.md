# 本地数据服务需求

## 1. 定位

本地数据服务是个人菜谱和本地任务的权威数据源，负责数据库、事务、迁移、
Repository 实现和一致性，不负责页面状态或业务展示。

当前承载位置以 `kitchen_recipe_data` 为主；是否继续拆包根据其他领域数据量
决定。

## 2. 服务对象

- 菜谱库。
- 菜谱编辑器。
- 导入处理服务。
- 手账阅读器。
- 烹饪运行时服务。
- 搜索服务。
- 备份与同步服务。

## 3. 职责

- 保存 Recipe、Ingredient、Step、Tag 和 Collection。
- 保存导入任务、原始材料引用和处理状态。
- 保存编辑草稿和用户确认状态。
- 保存 CookSession 和 CookRecord。
- 保存模板选择、资源引用和权益缓存。
- 提供事务、查询、Stream 和分页能力。
- 管理 Drift schema version 和迁移。
- 维护删除、归档和回收站规则。

## 4. 非职责

- 不执行 OCR 或 AI 推理。
- 不决定页面导航。
- 不直接渲染模板。
- 不读取广告或商店 SDK。
- 不将 Drift Row 暴露给 Presentation。

## 5. 数据分层

```text
SourceSnapshot
→ ExtractionDraft
→ UserRecipe
```

- 原始输入不可被结构化结果覆盖。
- AI 推断与用户编辑需要可区分。
- 用户编辑和确认字段具有更高优先级。
- 删除正式菜谱不隐式删除原始导入记录。

## 6. 写入要求

- 创建或更新完整菜谱使用事务。
- 菜谱、食材、步骤、标签和集合成员关系要么全部成功，要么全部回滚。
- 外部任务重试使用幂等键，避免重复记录。
- 写入失败保留编辑草稿。
- 批量操作明确最大批次和失败策略。

## 7. 查询要求

- 监听菜谱列表和筛选结果。
- 按 ID 获取完整菜谱详情。
- 获取菜谱集及成员。
- 获取阅读器范围快照。
- 获取导入任务及状态。
- 获取进行中的烹饪会话。
- 获取回收站和到期记录。
- 为搜索服务提供可索引字段。

## 8. 生命周期与清理

- 删除菜谱进入回收站，默认保留 30 天。
- 永久删除时清理无引用媒体资源。
- 归档不等于删除。
- 模板下架不删除菜谱的模板选择记录。
- 导入原始材料的清理需要用户可见策略。
- 清理任务可重试，不阻塞应用启动。

## 9. 迁移

修改 Drift 表时必须：

1. 增加 schema version。
2. 编写向前迁移。
3. 重新生成代码。
4. 增加迁移测试。
5. 验证旧数据升级后可读。
6. 说明无法回滚的字段变化。

禁止手动编辑生成文件。

## 10. 错误模型

至少区分：

- 数据不存在。
- 唯一约束冲突。
- 数据损坏。
- 磁盘空间不足。
- 事务失败。
- 迁移失败。
- 权限或文件不可访问。

底层异常转换为领域 Failure，页面不展示 SQL 或文件系统错误详情。

## 11. 验收

- 离线可创建、编辑、读取和删除菜谱。
- 事务中任一子项失败不会留下半份菜谱。
- 重新启动后编辑草稿和进行中任务可恢复。
- Stream 在相关数据变化后发出一致快照。
- 迁移测试覆盖至少一个旧 schema。
- Presentation 不依赖 Drift 类型。
