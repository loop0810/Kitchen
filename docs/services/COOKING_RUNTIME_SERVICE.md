# 烹饪运行时服务需求

## 1. 定位

烹饪运行时服务管理一次烹饪过程的会话、步骤进度、计时器、后台恢复、通知和
完成记录。它不负责菜谱编辑或手账渲染。

实现逐步烹饪时再决定是否建立独立 `kitchen_cooking` package。

## 2. 服务对象

- 菜谱详情。
- 逐步烹饪 Feature。
- 本地通知 Adapter。
- 屏幕常亮 Adapter。
- 本地数据服务。

## 3. 会话状态

```text
preparing
→ running
→ paused
→ completed

preparing / running / paused
→ abandoned
```

同一道菜是否允许多个进行中会话需要产品确认；MVP 建议只保留一个活跃会话。

## 4. 职责

- 从菜谱快照创建 CookSession。
- 保存本次份量和步骤快照。
- 记录当前步骤。
- 管理步骤前进、后退和跳转。
- 创建、暂停、恢复和取消计时器。
- 根据绝对时间恢复后台计时。
- 安排和取消本地通知。
- 自动保存进度。
- 完成后创建 CookRecord。
- 控制屏幕常亮状态并在退出后恢复。

## 5. 快照规则

开始烹饪时保存必要菜谱快照：

- 菜名。
- 本次份量。
- 食材和换算结果。
- 步骤顺序和文本。
- 每步时长、火力和温度。

用户在另一页面编辑正式菜谱，不应让进行中的步骤突然变化。新会话使用最新
菜谱版本。

## 6. 计时器

- 使用目标结束时间而不是仅依赖内存递减。
- 应用进入后台后根据系统时间恢复。
- 支持每个步骤至少一个基础计时器。
- 通知权限被拒绝时，应用内计时仍可用。
- 时区变化和系统时间调整需要安全处理。
- 计时器结束不自动跳到下一步。

## 7. 恢复

- 应用启动时检测进行中会话。
- 用户可继续或放弃。
- 恢复到原步骤和计时状态。
- 已过期计时器显示完成，而不是重新开始。
- 数据损坏时允许安全退出并保留问题说明。

## 8. 视觉和交互约束

- 大字号和高对比度。
- 大点击区域。
- 上一步和下一步位置稳定。
- 显示当前步骤和总进度。
- 不展示广告。
- 不使用复杂手账正文排版。
- 完全离线可用。

## 9. 平台能力

- 本地通知。
- 屏幕常亮。
- 后台时间恢复。
- 可选触觉反馈。

平台实现通过抽象 Adapter 接入，Domain 不依赖 Flutter Plugin。

## 10. 完成记录

允许记录：

- 完成时间。
- 实际用时。
- 本次份量。
- 成品照片。
- 本次调整。
- 是否还会再做。

CookRecord 与菜谱长期笔记分开。

## 11. 错误与降级

- 通知权限拒绝：保留应用内计时。
- 常亮失败：提示但不阻止烹饪。
- 写入进度失败：立即重试并提示风险。
- 菜谱被删除：进行中快照仍可完成，结束后说明来源已删除。
- 应用崩溃：下次启动恢复最近持久化状态。

## 12. 验收

- 无网络可完成一次完整烹饪。
- 后台超过计时结束时间后恢复显示正确。
- 重新启动应用可恢复步骤和计时。
- 编辑原菜谱不改变进行中会话。
- 通知权限拒绝不阻断步骤流程。
- 烹饪界面不出现广告。
