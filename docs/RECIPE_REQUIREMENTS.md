## 3. 产品定义

菜谱功能不是普通收藏列表，而是用户将外部内容整理成个人菜谱、以手账形式
归档、再次查找、查阅详细步骤并实际烹饪的核心系统。

核心闭环：

```text
手动创建或导入
→ 整理结构化菜谱
→ 选择手账模板
→ 保存到菜谱库
→ 加入一个或多个菜谱集
→ 搜索、筛选或翻阅菜谱集
→ 查看完整详情
→ 进入逐步烹饪
→ 记录本次调整
```

## 4. 产品原则

### 4.1 数据与表现分离

- 菜名、食材、步骤和笔记属于结构化菜谱数据。
- 手账模板、字体、颜色、贴纸和排版属于表现数据。
- 切换模板不得修改菜谱内容。
- 删除或下架模板不得导致菜谱数据丢失。

### 4.2 本地优先

- 浏览、编辑、搜索、阅读和烹饪必须离线可用。
- 已下载或已购买的模板应离线可用。
- 未来付费 AI、模板商城和同步失败不能阻断本地核心功能。

### 4.3 用户修改优先

- OCR、本地解析和未来 AI 生成内容只能作为草稿。
- 用户编辑、确认和调整后的内容不得被后续重新解析覆盖。
- 原始来源、结构化草稿和当前菜谱需要保留清晰关系。

### 4.4 美观不损害实用性

- 手账页可以强调个性和生活感。
- 完整详情与烹饪模式必须优先保证可读性。
- 详细步骤不能因为模板空间不足而被缩小、截断或隐藏。

## 5. 术语

### 5.1 菜谱

用户正式保存的结构化配方，包含基础信息、食材、步骤、来源和个人笔记。

### 5.2 手账页

一道菜谱的视觉摘要页。每页只展示一道菜，主要用于菜谱库缩略图和手账
阅读器，不展示完整步骤。

### 5.3 菜谱集

用户主动整理的一组菜谱。一道菜谱可以加入多个菜谱集，删除菜谱集不会删除
其中的菜谱。

本文档中的“已整理或已归档的菜谱集合”指已经创建并包含菜谱的菜谱集，不等同
于菜谱生命周期中的 `archived` 状态。

### 5.4 手账阅读器

以翻页方式连续浏览某一个菜谱集内手账页的只读界面。

### 5.5 菜谱详情

展示完整食材、准备工作、详细步骤、来源和长期笔记的页面。

### 5.6 烹饪模式

面向实际做菜场景的高可读步骤执行界面，与手账阅读器分离。

### 5.7 模板

定义手账页背景、装饰层、数据槽、字体和排版约束的可版本化资源。

## 6. 用户主要场景

### 6.1 创建并归档

1. 用户手动创建或确认一份导入草稿。
2. 用户填写菜名、食材、步骤等内容。
3. 用户选择一个免费、已购买或默认模板。
4. 系统生成手账页预览。
5. 用户保存菜谱并选择是否加入菜谱集。

### 6.2 从菜谱库查找

1. 用户打开菜谱库。
2. 用户通过滚动、搜索、筛选或排序找到手账缩略图。
3. 用户点击缩略图。
4. 系统直接进入该菜谱的完整详情。

### 6.3 翻阅一个菜谱集

1. 用户进入菜谱集区域。
2. 用户选择一个非空菜谱集。
3. 用户执行“翻阅菜谱集”。
4. 阅读器从排序后的第一道菜开始。
5. 用户左右滑动浏览当前菜谱集。
6. 用户点击某张手账进入该菜谱详情。
7. 返回后恢复原菜谱集和阅读位置。

### 6.4 实际烹饪

1. 用户从菜谱详情点击“开始烹饪”。
2. 系统展示食材和准备工作检查。
3. 用户逐步执行并使用计时器。
4. 系统自动保存进度。
5. 完成后用户可记录照片、用时和调整。

## 8. 菜谱生命周期

### 8.1 状态

```text
待完善 incomplete
可烹饪 ready
已归档 archived
已删除 deleted
```

### 8.2 状态含义

- `incomplete`：允许保存，但缺少部分建议字段。
- `ready`：已具备可查阅和烹饪的主要内容。
- `archived`：用户主动收起、不希望出现在默认列表中的历史菜谱。
- `deleted`：位于回收站，等待恢复或永久删除。

收藏和做过是独立属性，不是生命周期状态。

### 8.3 状态转换

- 草稿确认或手动保存后进入 `incomplete` 或 `ready`。
- 用户可以将 `ready` 或 `incomplete` 菜谱归档。
- 归档菜谱可以恢复为 `ready` 或 `incomplete`。
- 删除进入回收站，不立即永久清除。
- 回收站默认保留 30 天。

## 9. 菜谱库

### 9.1 基本结构

| ID | 优先级 | 需求 |
| --- | --- | --- |
| LIB-001 | P0 | 默认使用双列手账缩略图展示菜谱 |
| LIB-002 | P0 | 点击单张手账直接进入菜谱详情，不进入阅读器 |
| LIB-003 | P0 | 支持本地搜索 |
| LIB-004 | P0 | 支持全部、收藏、做过、待完善快速筛选 |
| LIB-005 | P1 | 支持分类、标签、时间、难度和烹饪方式筛选 |
| LIB-006 | P1 | 支持排序切换 |
| LIB-007 | P1 | 预留列表模式 |
| LIB-008 | P1 | 支持长按多选和批量操作 |
| LIB-009 | P1 | 支持回收站和恢复 |

默认排序仍为最近更新。手账阅读器使用独立的拼音阅读顺序，不改变菜谱库当前
排序。

### 9.2 软木板与竖屏布局

- 手账风格下使用低对比度竖向软木板作为列表背景。
- 双列纵向滚动，不复刻横向实体展板。
- 手账缩略图允许轻微旋转和上下错落。
- 旋转角度建议控制在 `-1.2°` 到 `1.2°`。
- 相邻缩略图不能真实遮挡点击区域。
- 搜索、筛选和创建操作必须保持清晰，不被软木纹理干扰。
- 极简风格使用更克制的纸张或列表表现，但业务入口保持一致。
- 大字体或窄屏设备允许降级为单列。

### 9.3 手账缩略图

展示内容：

- 当前模板的手账页缩略图。
- 菜名。
- 最多 4 项主要食材及数量。
- 收藏状态。
- 待完善状态。

不展示：

- 全部食材。
- 详细步骤。
- 长来源文本。
- 烹饪记录详情。

交互：

- 单击：进入菜谱详情。
- 收藏：使用独立按钮，不能触发详情跳转。
- 当前版本长按：在触点附近显示编辑菜谱、管理菜谱集和移入回收站浮层。
- 长按多选属于后续批量操作能力，上线时不得与当前长按浮层产生手势冲突。
- 装饰元素不响应点击，也不进入无障碍语义树。

### 9.4 状态页面

- 无菜谱时引导用户使用统一“创建菜谱”入口。
- 搜索无结果时展示清除搜索和筛选入口。
- 加载失败时提供重试，不展示技术错误栈。
- 模板资源缺失时使用内置默认模板，菜谱仍可打开。

## 10. 搜索、筛选与排序

### 10.1 本地搜索

P0 搜索字段：

- 菜名。
- 食材名称。
- 主分类。
- 用户标签。

P1 搜索字段：

- 简介。
- 步骤文本。
- 长期笔记。
- 来源作者或平台。

搜索结果必须属于用户个人菜谱库，第一版不调用云端 AI。

### 10.2 快速筛选

- 全部。
- 收藏。
- 做过。
- 待完善。

### 10.3 高级筛选

- 主分类。
- 用户标签。
- 主要食材。
- 烹饪方式。
- 总时间区间。
- 难度。
- 是否有成品图。
- 是否已加入菜谱集。

### 10.4 菜谱库排序

- 最近更新。
- 最近保存。
- 最近做过。
- 最常制作。
- 菜名。
- 用户自定义顺序，P2。

## 11. 菜谱集

### 11.0 当前版本边界

本轮“归档”表示把菜谱整理进菜谱集，不提供生命周期 `archived` 的操作入口。
菜谱库使用可点击、可左右滑动的 `[菜谱] [菜谱集]` 分段，并分别保留页面状态。
集合允许重名，名称去除首尾空格后不能为空且最多 40 字；按创建时间升序稳定展示，
不提供集合自身排序。当前版本完成书籍封面、有序成员管理和基础手账阅读器；单击
非空书籍直接翻阅，单击空书籍进入成员添加引导，简介留到后续。

### 11.1 基本能力

| ID | 优先级 | 需求 |
| --- | --- | --- |
| COL-001 | P0 | 创建菜谱集 |
| COL-002 | P0 | 重命名菜谱集 |
| COL-003 | P0 | 将菜谱加入或移出菜谱集 |
| COL-004 | P0 | 一道菜谱允许加入多个菜谱集 |
| COL-005 | P0 | 删除菜谱集不删除菜谱 |
| COL-006 | P1 | 按创建时间稳定展示菜谱集 |
| COL-007 | P1 | 从相册选择、裁切、替换或删除自定义封面 |
| COL-008 | P1 | 批量添加或移除菜谱 |
| COL-009 | P1 | 侧滑移除成员并撤销 |
| COL-010 | P1 | 长按拖动并原子保存成员顺序 |

### 11.2 书籍列表与管理入口

- 正常宽度使用响应式双列 3:4 书籍卡片，大文字或极窄宽度降级为单列。
- 无自定义封面时按集合 ID 使用稳定柔和配色和内置书封插画；自定义封面填满书封，
  图片损坏或读取失败时回退内置书封。
- 书籍显示名称和有效成员数量，具有书脊、页边和阴影。
- 单击非空集合直接进入阅读器，单击空集合进入成员添加引导；长按在触点附近显示
  编辑、管理成员和删除菜谱集。
- 编辑与创建复用名称和封面弹框；封面只从系统相册选择并固定为 3:4 手动裁切，
  不请求相机权限。
- 删除菜谱集需确认，并明确不会删除成员菜谱。

### 11.3 成员管理

- 成员管理页从书籍长按菜单进入；空集合也可通过单击书封进入添加引导。
- 新成员按用户勾选顺序追加到末尾，不改变既有成员顺序。
- 向左侧滑露出“移除”，移除后立即显示撤销；撤销恢复原位置。
- 长按拖动成员，释放后一次性原子保存完整可见成员顺序。
- 已软删除菜谱不显示，恢复后按保留位置重新出现。

菜谱成员点击后直接进入对应菜谱详情，不直接进入阅读器。

### 11.4 阅读器可用条件

- 菜谱集至少包含一道未删除菜谱。
- 空菜谱集不进入阅读器，单击后进入成员管理页并提示先添加菜谱。
- 已删除成员自动从阅读器范围排除。
- `incomplete` 菜谱允许被显式加入并展示“待完善”状态。
- `archived` 菜谱如果仍属于菜谱集，可以继续在该菜谱集中翻阅。

## 12. 手账模板系统

### 12.1 模板目标

模板类似表盘：模板预留数据槽，系统将当前菜谱的结构化字段填入指定位置。

每张手账页只负责菜谱摘要，因此固定槽位方案可用于第一版。

### 12.2 模板槽位

P0 槽位：

- 菜名。
- 主要食材 1～4。
- 每项主要食材的数量文本。
- 详情入口的视觉位置。

P1 槽位：

- 分类。
- 准备时间和烹饪时间。
- 难度。
- 成品图。
- 自定义短备注。

装饰层：

- 背景纸张。
- 胶带。
- 贴纸。
- 活页孔。
- 图钉。
- 分割线和色块。

### 12.3 模板定义

模板至少包含：

```text
TemplateDefinition
├── id
├── version
├── name
├── author
├── aspectRatio
├── previewAsset
├── backgroundAsset
├── slots[]
├── decorationLayers[]
├── bundledFonts[]
├── minimumAppVersion
└── entitlementType
```

槽位至少包含：

```text
TemplateSlot
├── kind
├── rect
├── alignment
├── textStyle
├── maxLines
├── overflowRule
├── visibleInThumbnail
└── accessibilityLabel
```

### 12.4 渲染规则

- 使用固定设计画布和等比例缩放，不能按设备写死像素坐标。
- 缩略图和阅读器复用同一个模板定义。
- 菜名和主要食材不得被装饰遮挡。
- 内容超长时按模板规则截断摘要，但完整内容必须在详情页可见。
- 菜名和食材名过长时优先截断名称；食材数量使用独立区域，不得因名称过长而
  完全消失。
- 模板缺失、损坏或版本不兼容时使用内置默认模板。
- 模板装饰层不得进入无障碍语义树。
- 模板切换只改变表现，不改变菜谱内容。

### 12.5 模板选择

- 创建菜谱时可以选择模板。
- 未选择时继承全局默认模板。
- 保存后可以在菜谱详情或编辑页更换模板。
- 更换模板前展示实时预览。
- 用户购买或下载的模板必须本地缓存。

### 12.6 主要食材规则

P0：

- 按用户维护的食材顺序选择前 4 项。
- 展示用户保存的原始数量文本。
- 不足 4 项时留空，不生成虚构内容。

P1：

- 支持用户显式标记主要食材。
- AI 可以建议主要食材，但需要用户确认。
- 显式标记优先于自动顺序。

### 12.7 免费与付费模板

- 提供足够完成核心体验的免费模板。
- 付费模板采用一次性买断。
- 已购买模板应支持恢复购买。
- 模板下架后，已购买用户仍可使用兼容版本。
- 模板权益与未来 AI 付费权益分开建模。
- 支付能力上线前不得在客户端伪造购买状态。

### 12.8 模板编辑器

P2 提供受约束的模板编辑器，而不是任意文档编辑器。

允许：

- 移动、缩放和旋转槽位。
- 修改文字颜色、字体、字号和对齐。
- 增加、删除和排列贴纸。
- 设置背景和胶带。
- 使用网格和对齐线。
- 撤销与重做。
- 使用示例菜谱预览。

模板编辑器操作的是菜名槽、食材槽等数据槽，不直接嵌入某一道菜的完整文字。

### 12.9 用户模板上传

P3：

- 用户可以提交自己制作的可复用模板。
- 上传前必须执行结构、容量、资源和版本校验。
- 公开模板必须经过内容、版权和质量审核。
- 需要举报、屏蔽、下架、版权投诉和作者申诉机制。
- 模板版本发布后不可覆盖破坏旧版本。

### 12.10 未来贡献奖励

- 模板贡献奖励的具体形式尚未确认，不默认发放 AI 次数。
- 模板所有权使用 `TemplateEntitlement`，不能与未来奖励余额混用。
- 奖励由服务端记账。
- 奖励触发条件、每日上限和反作弊规则由服务端控制。
- 模板审核通过不必等同于现金收益。
- 如果未来提供现金分成，需要作为独立创作者结算项目评审。

## 13. 手账阅读器

> 当前版本实现本章 P0 基础翻阅能力；跨启动阅读位置和高级翻页效果留到后续。

### 13.1 定位

手账阅读器是只读的菜谱集翻阅工具，不是：

- 菜谱库默认入口。
- 菜谱编辑器。
- 完整菜谱详情。
- 逐步烹饪模式。

阅读器内不提供菜谱集编辑、成员管理或其他管理操作；这些操作留在菜谱库及集合
成员管理页。

### 13.2 入口

| ID | 优先级 | 需求 |
| --- | --- | --- |
| RDR-001 | P0 | 单击非空菜谱集书封直接打开阅读器，空集合进入添加引导 |
| RDR-002 | P0 | 单击菜谱库或菜谱集中的菜谱不打开阅读器 |
| RDR-003 | P0 | 打开时阅读范围固定为所选菜谱集 |
| RDR-004 | P0 | 不允许滑动进入集合外菜谱 |

### 13.3 单页内容

每页只展示一道菜谱：

- 菜名。
- 最多 4 项主要食材及数量。
- 当前模板和装饰。
- 当前页码。
- “查看详细步骤”入口。
- 待完善标记，适用时展示。

不展示：

- 全部食材。
- 详细步骤。
- 长期笔记全文。
- 来源全文。
- 广告。

### 13.4 阅读顺序

当前规则：

1. 中文标题排在英文标题之前。
2. 中文按完整拼音排序，以拼音首字母形成 `A-Z` 分组。
3. 英文忽略大小写按字母顺序排列。
4. 数字、符号、Emoji 和无法生成排序键的标题最后排列。
5. 排序键相同时使用标准化标题和菜谱 ID 保证稳定。

混合标题按第一个有效文字字符判断语言分组。

MVP 使用拼音转换器默认处理多音字。P2 可增加用户可修正的排序读音。

未来国际化时，排序必须通过可替换的 `RecipeReadingOrderPolicy` 实现，不在
Widget 中写死中文逻辑。

### 13.5 初始位置

- 阅读器通过菜谱集打开，不存在单张菜谱的初始定位参数。
- 第一次进入默认显示排序后的第一道菜谱。
- 从菜谱详情返回时恢复进入详情前的页码。
- P1 可以记录每个菜谱集上次阅读位置；上线前需要提供设置或清晰提示。

### 13.6 翻页交互

- 左右滑动切换菜谱。
- 到达集合首尾时停止并提供系统回弹反馈。
- MVP 不循环翻页。
- MVP 使用 `PageView`、阴影和轻微缩放表达翻书感。
- 真正的卷页、折角或 Shader 动画属于 P2。
- 页面切换期间不能误触详情入口。

### 13.7 进入详情

- 点击当前手账页进入该菜谱详情。
- “查看详细步骤”按钮进入同一详情页面。
- 两个入口行为一致。
- 返回时保持阅读器实例、菜谱集范围和当前页码。
- 详情页中的编辑或收藏变化返回后应更新当前手账内容。

### 13.8 范围快照

进入阅读器时创建当前菜谱集成员 ID 的有序快照：

- 阅读过程中新增成员不突然插入当前序列。
- 移除成员不导致当前页无预期跳动。
- 当前菜谱被永久删除时跳到相邻有效页面。
- 重新进入阅读器时重新计算集合成员和排序。

## 14. 手动创建与编辑

### 14.1 基础信息

P0：

- 菜名。
- 简介。
- 主分类。
- 标签。
- 基准份量。
- 准备时间。
- 烹饪时间。
- 难度。
- 封面或成品图。
- 手账模板。

### 14.2 食材

每项食材保存：

- 名称。
- 原始数量文本。
- 可选数值。
- 可选单位。
- 预处理方式。
- 是否可选。
- 是否参与份量换算。
- 排序位置。
- P1 主要食材标记。

允许“适量”“少许”“一小把”等无法可靠数值化的文本。

### 14.3 步骤

每个步骤保存：

- 顺序。
- 可选标题。
- 详细说明。
- 可选时长。
- 可选火力。
- 可选温度。
- 关联食材，P1。
- 步骤图片，P1。

### 14.4 编辑体验

- 复杂编辑使用独立编辑页面。
- 手账预览明确提示缩略图最多展示前 4 项食材，未展示的食材仍完整保存并可在
  详情中查看。
- 当前最小创建流程的硬必填项为菜名、主分类和可用模板；菜名为空或超过
  120 个字符时必须在对应字段显示错误，不能只显示通用保存失败。
- 保存时必须基于完整输入模型一次性计算并保存全部字段错误，不得依赖字段当前
  是否位于屏幕内；错误字段重新进入屏幕时仍显示对应错误状态。
- 无论错误数量多少，全局轻提示只显示按表单顺序排列的第一条具体错误，例如
  “请输入菜名”，不使用含义模糊的通用校验提示。
- 食材或步骤允许暂时为空，并按既有规则保存为 `incomplete`，不作为硬必填。
- 食材和步骤支持新增、删除和排序。
- 编辑草稿自动保存在本地。
- 正式保存使用数据库事务。
- 离开未保存编辑时明确提示。
- 保存失败不得丢失本地草稿。
- 模板预览失败不阻止保存结构化菜谱。

## 15. 菜谱详情

### 15.1 展示顺序

1. 封面、菜名和简介。
2. 份量、时间、难度和分类。
3. 标签。
4. 食材和用量。
5. 准备工作。
6. 全部详细步骤。
7. 用户长期笔记。
8. 来源。
9. 固定的“开始烹饪”按钮。

### 15.2 入口来源

菜谱详情可以来自：

- 菜谱库缩略图。
- 首页或搜索结果。
- 菜谱集成员。
- 手账阅读器。
- 创建或导入完成页。
- 烹饪记录。

详情页不应根据入口复制业务页面，只保存必要的返回上下文。

创建成功进入详情时必须保留创建入口之前的来源页路由；详情页提供返回按钮，
并在支持的平台保留系统边缘返回手势。

### 15.3 操作

- 收藏或取消收藏。
- 编辑菜谱。
- 更换手账模板。
- 加入或移出菜谱集。
- 开始烹饪。
- 归档。
- 删除到回收站。
- 查看来源。
- P1 调整临时份量。

## 16. 份量换算

- 只缩放明确数值。
- “适量”等文本保持不变。
- 允许食材关闭自动换算。
- 不自动缩放火力、时间、锅具尺寸。
- 详情页临时换算不修改基准配方。
- 换算结果需要明确显示当前份量与基准份量。

## 17. 逐步烹饪模式

### 17.1 开始前

- 展示完整食材清单。
- 展示准备工作。
- 允许调整本次份量。
- 显示未完成或低可信内容提示。

### 17.2 执行中

- 一次聚焦一个步骤。
- 展示当前步骤和总进度。
- 展示本步骤使用的食材和用量。
- 展示火力、温度和时间。
- 支持上一步和下一步。
- 支持左右滑动。
- 支持步骤计时器。
- 退到后台后计时继续。
- 支持本地通知。
- 自动保存进度。
- 支持重新进入恢复。
- 支持屏幕常亮开关。

### 17.3 视觉约束

- 大字号。
- 高对比度。
- 大点击区域。
- 不使用复杂手写正文字体。
- 不展示广告。
- 完全离线可用。

## 18. 烹饪记录与长期笔记

### 18.1 烹饪记录

每次完成后可选记录：

- 完成时间。
- 实际用时。
- 本次照片。
- 本次调整。
- 是否还会再做。
- 本次份量。

### 18.2 长期笔记

- 属于菜谱本身。
- 用于记录稳定的口味、锅具或火候经验。
- 与单次烹饪记录分开保存。
- 删除单次记录不影响长期笔记。

## 19. 导入与菜谱确认

### 19.1 数据层次

```text
原始来源材料
→ OCR 与本地解析草稿
→ 用户确认后的当前菜谱
```

### 19.2 字段来源

字段需要区分：

- 来源明确提供。
- 本地推断或未来 AI 推断。
- 用户编辑。
- 用户确认。

重新解析不得覆盖用户编辑和确认内容。

### 19.3 结构化草稿确认

用户可以：

- 修改任意字段。
- 调整食材顺序。
- 调整步骤顺序。
- 选择主要食材。
- 选择手账模板。
- 保存为待完善。
- 保存并查看详情。
- 暂存稍后处理。

- P0 可以在 UseCase 中为当前集合计算排序键。

- 标题修改时必须使旧排序键失效。
- Domain 不依赖 Flutter 或数据库生成类型。

## 21. 商业化与创作者生态

### 21.1 模板商品

- 免费模板始终提供完整核心能力。
- 付费模板一次性买断。
- 商品价格、权益和恢复由平台购买系统管理。
- iOS 与 Android 权益是否跨平台，需要账号和服务端权益系统支持。
- 不在没有账号或服务端校验时承诺跨平台恢复。

### 21.2 未来付费 AI 权益

- AI 辅助不属于当前 MVP，未来作为用户主动选择的付费能力。
- 订阅、次数包或组合方式在商业化版本前另行确认。
- 若采用 Credit，服务端失败需要退还已扣次数。
- Credit 不可转让、不可提现。
- 客户端不保存服务 API 密钥，也不作为额度权威来源。

### 21.3 公开模板治理

模板上传功能上线前必须具备：

- 用户协议和模板授权声明。
- 自动与人工审核。
- 举报和下架。
- 用户屏蔽。
- 版权投诉。
- 作者申诉。
- 违规记录和重复上传检测。
- 服务端资源扫描。

## 22. 非功能需求

### 22.1 性能

- 常规菜谱库滚动保持流畅。
- 模板资源按尺寸解码，避免加载超大原图。
- 装饰层尽量复用并缓存。
- 长列表只构建可见项目。
- 大量模板缩略图后续可缓存为栅格预览。
- 避免在列表滚动时反复执行昂贵的图片合成。

### 22.2 离线

- 已保存菜谱、菜谱集和已下载模板离线可用。
- 阅读器和详情离线可用。
- 云端模板下载失败使用本地默认模板。
- 网络恢复后由明确任务重试，不阻断本地交互。

### 22.3 可访问性

- 手账缩略图具有菜名、主要食材和状态语义。
- 装饰贴纸不加入语义树。
- 详情与烹饪模式支持系统文字缩放。
- 关键图标提供 Tooltip 或语义标签。
- 颜色不能作为状态的唯一表达方式。
- 大字体模式允许菜谱库降级为单列。

### 22.4 隐私和版权

- 个人菜谱默认不公开。
- 保留来源平台、链接和作者信息。
- 不提供绕过登录、反爬或付费内容限制的能力。
- 上传图片或文字到云端前首次明确告知。
- 用户可以删除保存的原始材料。

### 22.5 可靠性

- 编辑草稿不能因意外退出丢失。
- 数据库修改通过事务完成。
- 模板损坏不能阻止读取菜谱详情。
- 阅读器成员变化不能导致崩溃或越界。
- Drift 表变更必须提供 schema 升级、迁移和数据库测试。

## 23. 架构边界

```text
app
├── kitchen_recipe_library
├── kitchen_recipe_editor
├── future kitchen_cooking
├── kitchen_recipe_data ──> kitchen_recipe_domain
├── kitchen_design_system
└── kitchen_app_core
```

- `kitchen_recipe_domain` 定义 Recipe、Collection、模板选择标识、UseCase 和
  Repository 接口。
- `kitchen_recipe_data` 保存菜谱、集合成员、模板选择和排序派生数据。
- `kitchen_recipe_library` 负责菜谱库、菜谱集、手账阅读器和详情的业务展示。
- `kitchen_design_system` 提供纸张、胶带、贴纸、阴影等无业务含义的组件。
- 模板渲染器如果同时被编辑器、菜谱库和导出功能使用，应评估独立 package。
- Feature 之间不直接依赖，路由和依赖由根 App 装配。
- Presentation 不直接使用 Drift 类型。

## 24. 事件与指标

在不收集菜谱正文的前提下，可以记录：

- 创建菜谱开始、保存成功和放弃。
- 导入草稿确认成功。
- 菜谱搜索和无结果。
- 菜谱详情打开来源。
- 菜谱加入或移出菜谱集。
- 菜谱集开始翻阅。
- 阅读器页数和进入详情。
- 模板选择、更换、下载和购买。
- 烹饪开始、中断、恢复和完成。
- AI 调用成功、失败和降级方式。

禁止将用户菜名、食材、步骤、笔记或原始导入正文作为普通分析事件上传。

## 25. 异常与边界场景

- 菜谱没有主要食材：手账页保留空白或显示“食材待补充”。
- 菜名超长：手账摘要按模板限制行数，详情展示完整名称。
- 模板字体缺失：使用模板声明的安全回退字体。
- 模板已下架：使用本地兼容版本或默认模板。
- 菜谱集为空：禁止进入阅读器。
- 阅读器当前菜谱被删除：移动到相邻有效页；无有效页时退出并提示。
- 菜谱集被删除：已打开的阅读器允许安全返回，不继续写入已删除集合。
- 菜谱标题修改：下次进入阅读器按新拼音位置排序。
- 多音字排序不符合预期：MVP 接受默认读音，后续允许修正。
- 详情编辑后返回阅读器：当前页内容刷新，范围和页码保持。
- 大字体导致模板摘要溢出：摘要按模板规则处理，详情不受影响。

## 26. 分阶段交付

### 26.1 阶段 A：最小手账闭环

- 点击手账直接进入详情。
- 创建、编辑和删除菜谱集。
- 从非空菜谱集进入阅读器。

- 点击阅读器手账进入详情。
- 模板缺失降级。

### 26.2 阶段 B：完整菜谱使用

- 完整菜谱编辑。
- 主要食材显式标记。
- 完整详情。
- 逐步烹饪。
- 烹饪进度恢复。
- 烹饪记录。

### 26.4 阶段 D：模板创作生态

- 受约束模板编辑器。

### 26.5 阶段 E：长期扩展

- 公共菜谱发现。

- [ ] 缩略图展示菜名和主要食材及数量。

## 28. 已确认决策

- 菜谱库不再使用传统 Material 菜谱卡片作为目标形态。
- 菜谱库展示手账页缩略图。
- 点击单张手账直接进入完整菜谱详情。
- 手账阅读器只能通过选择非空菜谱集打开。
- 阅读器每页只展示一道菜谱摘要，不展示详细步骤。
- 阅读器范围固定为当前菜谱集。
- 阅读器首次进入定位到排序后的第一道菜。
- 中文菜名排在英文菜名之前。
- 中文按拼音、英文忽略大小写排序。
- 详细步骤属于菜谱详情和烹饪模式。
- 第一版采用固定模板和数据槽，不实现自由编辑器。
- 模板编辑、上传、付费和创作者奖励分阶段实现。
