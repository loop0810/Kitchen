# 厨房手记：产品与架构决策记录

本文档记录已经确认的重要决策、原因和影响范围。它不替代需求文档，而是用于
回答“为什么这样设计”，避免后续对话或实现重新引入已排除的方案。

## 使用规则

- 新决策使用递增编号。
- 修改既有决策时新增一条“替代”记录，不直接删除历史原因。
- 状态使用：已确认、待验证、已替代、已废弃。
- 需求文档记录最终行为，本日志记录决策过程。

## 决策列表

### D-001 使用 Flutter 同时发布 iOS 与 Android

- 状态：已确认
- 时间：2026-07
- 决策：客户端使用 Flutter，保留必要的平台桥接能力。
- 原因：满足双平台发布和 Flutter 架构学习目标。
- 影响：平台能力通过 Adapter 或 Plugin 边界接入，避免业务层依赖平台实现。

### D-002 核心能力本地优先

- 状态：已确认
- 时间：2026-07
- 决策：浏览、编辑、搜索、详情和烹饪不依赖网络。
- 原因：菜谱在厨房场景需要稳定可用，云端成本和可用性不可控。
- 影响：本地数据库是个人菜谱权威源，云端能力必须可降级。

### D-003 视觉面向核心女性用户但保持包容

- 状态：已确认
- 时间：2026-07
- 决策：提供温暖生活化的手账风格，同时提供极简风格。
- 原因：匹配早期核心用户审美，又不排斥其他用户。
- 影响：文案和图像避免性别排他；业务页面不能为两种风格复制。

### D-004 AI 手绘不进入首版

- 状态：已确认
- 时间：2026-07
- 决策：首版使用模板化手账，不生成完整手绘步骤图。
- 原因：生成成本、稳定性和视觉一致性风险较高。
- 影响：AI 手绘作为未来付费增强能力。

### D-005 AI 使用端侧优先、云端受限的分层策略

- 状态：已确认
- 时间：2026-07
- 决策：依次使用 OCR、本地规则、端侧模型和受限云端 AI。
- 原因：降低持续成本，保证免费产品可持续并支持离线降级。
- 影响：云端调用通过抽象和服务端代理；客户端不保存密钥。

### D-006 激励广告只用于用户主动补充 AI 次数

- 状态：已确认
- 时间：2026-07
- 决策：用户主动观看广告后获得有限 AI Credit。
- 原因：尝试用广告收入平衡云端推理支出。
- 影响：广告不出现在启动、浏览、编辑、详情和烹饪流程。

### D-007 首页保持极简

- 状态：已确认
- 时间：2026-07
- 决策：首页仅保留主文案、搜索、快速导入和手动创建。
- 原因：其他内容与菜谱库重复，会增加首页复杂度。
- 影响：收藏、最近使用、统计和推荐整合到菜谱库或“我的”。

### D-008 使用多 package 组件化架构

- 状态：已确认
- 时间：2026-07
- 决策：将 App、Domain、Data、Design System 和 Feature 分离。
- 原因：项目同时承担 Flutter 架构和跨组件通信学习目标。
- 影响：Feature 不互相依赖，根 App 负责装配和协调。

### D-009 菜谱库目标形态为手账缩略图

- 状态：已确认
- 时间：2026-07-28
- 决策：传统 Material 菜谱卡片改为软木板上的手账页缩略图。
- 原因：手账是核心产品表达，不只是颜色主题。
- 影响：业务数据保持不变，模板渲染与缩略图成为核心能力。

### D-010 首版使用固定模板和数据槽

- 状态：已确认
- 时间：2026-07-28
- 决策：模板类似表盘，预留菜名和主要食材等数据槽。
- 原因：实现成本和适配风险显著低于自由编辑器。
- 影响：自由模板编辑器、上传和商城分阶段实现。

### D-011 手账页只展示摘要

- 状态：已确认
- 时间：2026-07-28
- 决策：每张手账只展示菜名、部分主要食材和数量，不展示详细步骤。
- 原因：固定模板无法可靠承载任意长度步骤，摘要更适合翻阅。
- 影响：完整内容由菜谱详情和烹饪模式负责。

### D-012 单张手账直接进入菜谱详情

- 状态：已确认
- 时间：2026-07-28
- 决策：点击菜谱库或菜谱集里的手账直接进入完整详情。
- 原因：用户对单道菜的主要意图是查看完整内容，不需要先经过阅读器。
- 影响：阅读器不再是单张菜谱的中间页面。

### D-013 手账阅读器只从菜谱集打开

- 状态：已确认
- 时间：2026-07-28
- 决策：用户选择非空菜谱集并执行“翻阅菜谱集”后进入阅读器。
- 原因：阅读器表达翻阅一本整理好的菜谱册，需要明确且有限的内容范围。
- 影响：阅读器不能滑动到当前菜谱集之外；首次从第一道菜开始。

### D-014 阅读器使用中文优先拼音顺序

- 状态：已确认
- 时间：2026-07-28
- 决策：中文标题在英文标题前；中文按拼音、英文忽略大小写排序。
- 原因：当前首发语言为中文，并需要稳定的翻阅顺序。
- 影响：排序策略需可替换，为未来国际化保留边界。

### D-015 模板所有权与 AI Credit 分离

- 状态：已确认
- 时间：2026-07-28
- 决策：模板使用 Entitlement，AI 次数使用不可转让和不可提现的 Credit。
- 原因：避免权益、消耗额度和真实货币混成一个难以审计的余额系统。
- 影响：付费模板、广告奖励和模板贡献奖励分别记账。

### D-016 共享模板能力使用独立 package

- 状态：已确认
- 时间：2026-07-28
- 决策：模板模型、注册校验、版本解析和 Flutter 渲染由
  `kitchen_recipe_template` 统一承载。
- 原因：编辑器、菜谱库、未来阅读器和导出都会复用模板，同时 Design System
  不能依赖菜谱业务，Feature 之间也禁止直接依赖。
- 影响：模板 package 只依赖 Recipe Domain；模板选择由 Domain 表达并由 Data
  持久化，Feature 只消费公共渲染接口。

### D-017 创建错误就地展示并保留详情返回栈

- 状态：已确认
- 时间：2026-07-29
- 决策：创建菜谱的硬必填错误在对应字段就地展示；创建成功进入详情时替换
  创建页但保留其来源页。
- 原因：通用“保存失败”无法帮助用户修正输入，清空整个导航栈也会导致详情页
  缺少返回按钮和系统边缘返回手势。
- 影响：Domain UseCase 在写入前执行类型化校验；Presentation 映射字段错误；
  食材或步骤缺失仍允许保存为待完善。

### D-018 保存校验同时提供字段错误和全局提示

- 状态：已确认
- 时间：2026-07-29
- 决策：长表单保存校验失败时，保留字段下方具体错误，并同步显示全局轻提示。
- 原因：用户从表单底部保存时，错误字段可能已滚出屏幕，仅就地展示无法及时
  反馈保存未执行的原因。
- 影响：顶部和底部保存入口复用同一校验反馈，通用提示不替代具体字段错误。

### D-019 完整模型校验替代可见 FormField 校验

- 状态：已确认，替代 D-018 中的通用轻提示策略
- 时间：2026-07-29
- 决策：点击保存时校验完整输入模型并一次性写入全部字段错误状态；全局轻提示
  只显示第一条具体错误。
- 原因：长列表会回收离屏 FormField，依赖当前挂载字段会漏掉错误状态；通用
  提示也无法直接告诉用户应先修正哪一项。
- 影响：字段是否可见不再影响校验结果；滚回离屏字段后仍能看到错误标识。

### D-020 食材使用单一有序列表

- 状态：已确认
- 时间：2026-07-29
- 决策：菜谱不设计“主料”“调料”等食材分组，全部食材只按用户维护的单一顺序
  保存和展示。
- 原因：分组增加创建、编辑和阅读复杂度，但不属于当前菜谱整理所需的信息结构。
- 影响：移除 `IngredientGroup` 领域实体、食材分组外键与界面分组标题；旧数据升级
  时保留全部食材及原有顺序，仅删除分组元数据。

### D-021 主动创建统一收口并将导入建模为持久化任务

- 状态：已确认
- 时间：2026-07-29
- 决策：首页、菜谱库和导入箱复用同一个“创建菜谱”选择面板，面板只提供
  手动创建、粘贴文章或链接、选择图片；系统分享直接进入导入箱。
- 原因：创建方式选择属于全局协调，不应由各 Feature 各自实现；导入处理可能
  被系统中断，原始输入和中间结果必须先持久化并可恢复。
- 影响：新增纯 Dart `kitchen_import_domain` 与 Drift
  `kitchen_import_data`；根 App 负责导入草稿到菜谱编辑器的映射，并以唯一
  `importTaskId` 保证重复确认不会创建重复菜谱。

### D-022 Android 系统分享使用原生暂存清单交接

- 状态：已确认
- 时间：2026-07-30
- 决策：Android 接收文字、链接、单图和多图分享时，原生层先把载荷复制到应用
  私有目录并原子写入版本化清单；根 App 创建持久化 ImportTask 后才确认并清理
  暂存清单。
- 原因：第三方 Content URI 的读取授权可能随 Activity 或进程结束而失效，直接
  把 URI 交给异步 OCR 会造成冷启动和中断恢复时丢失原始输入。
- 影响：Android 冷启动与前台分享使用同一消费流程；文字与图片可保存在同一
  ImportTask，图片 OCR 与分享文案随后统一进入结构化流程。iOS 仍需独立的
  Share Extension 与 App Group 清单实现。

### D-023 菜谱整理使用分段菜谱集入口

- 状态：已确认
- 时间：2026-08-01
- 决策：本轮“归档”表示整理进菜谱集；菜谱库使用 `[菜谱] [菜谱集]` 分段，
  集合允许重名并由用户拖动排序。
- 原因：菜谱集是多对多整理关系，不应与菜谱生命周期 `archived` 混淆。
- 影响：本轮不提供生命周期归档操作，也不实现手账阅读器、自定义封面和简介。

### D-024 回收站保留删除前状态与集合关系

- 状态：已确认
- 时间：2026-08-01
- 决策：菜谱软删除保留 30 天，单独记录删除时间和删除前生命周期状态；软删除
  不移除集合关系，永久删除才级联清理。
- 原因：恢复应回到删除前语义和整理位置，不能把历史 `archived` 菜谱错误恢复为
  默认列表状态。
- 影响：启动、恢复前台和打开回收站时机会式清理到期记录，失败留待下次重试。

### D-025 菜谱库排序偏好由 Data 持久化

- 状态：已确认
- 时间：2026-08-01
- 决策：菜谱库提供五种固定排序并保存上次选择；中文标题使用完整拼音排序，英文
  忽略大小写，数字和符号最后。
- 原因：排序属于用户可恢复偏好，Feature 不应直接访问数据库或自行维护不稳定的
  标题排序规则。
- 影响：Domain 暴露类型化排序与偏好契约，Data 负责持久化和拼音排序键。

### D-026 菜谱管理操作前置到卡片长按浮层

- 状态：已确认
- 时间：2026-08-01
- 决策：长按菜谱库手账缩略图，在触点附近显示编辑、管理菜谱集和移入回收站；
  详情页不再重复提供这些管理入口。
- 原因：管理菜谱属于列表整理流程，先进入详情再打开菜单路径过深。
- 影响：单击仍进入只读详情；收藏按钮保持独立；未来引入长按多选前需要重新设计
  与当前浮层的手势关系。

### D-027 菜谱集采用书籍封面与有序成员模型

- 状态：已确认，替代 D-023 中集合拖动排序与无自定义封面的边界
- 时间：2026-08-01
- 决策：菜谱集按创建时间升序展示为响应式书籍网格，单击本轮不响应；长按提供
  编辑、管理成员和删除。封面从相册选择并固定 3:4 裁切，成员支持追加、侧滑撤销
  移除和原子拖动排序。
- 原因：集合列表要形成清晰的“菜谱书”整理心智，同时为下一迭代非循环全屏阅读器
  保留单击入口；成员顺序属于集合内容，不应与集合自身排序混淆。
- 影响：菜谱数据库升级至 v6，集合保存受控相对封面路径，成员保存独立位置；旧
  集合位置列保留但不再公开排序 UseCase。

### D-028 导入箱统一侧滑确认删除

- 状态：已确认
- 时间：2026-08-01
- 决策：导入箱所有状态均可向左侧滑露出删除按钮；处理中任务先取消再删除，已保存
  任务只删除导入记录，其他任务同时清理受控媒体。
- 原因：失败页单独删除无法覆盖积压任务，完全滑动直接删除又容易误操作；处理期间
  删除必须成为流水线的正常终止条件。
- 影响：列表和详情复用状态化确认文案，Import Pipeline 将记录消失视为安全取消，
  Data 只清理 `import_media` 受控目录并机会式回收孤立文件。
