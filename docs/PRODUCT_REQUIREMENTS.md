## 3. 产品概述

厨房手记是一款本地优先的个人菜谱管理和烹饪应用。用户可以把来自短视频、
图文平台、网页、截图和个人笔记的内容整理为结构化菜谱，并以极简或手账形式
保存、查找、翻阅和实际烹饪。

核心闭环：

```text
发现内容
→ 统一创建入口或系统分享
→ 结构化 OCR / 本地保守解析
→ 用户确认和修正
→ 保存为个人菜谱
→ 选择手账模板并加入菜谱集
→ 搜索、筛选或翻阅
→ 查看完整步骤
→ 逐步烹饪
→ 记录个人调整
```

## 4. 产品目标

### 4.1 用户目标

- 快速保存分散在不同平台的做饭内容。
- 将视频和截图转换为可快速阅读的结构化菜谱。
- 通过搜索、分类、标签和菜谱集重新找到内容。
- 用具有个人表达的手账形式积累自己的菜谱本。
- 做饭时获得清晰、可靠、可恢复的步骤指引。
- 长期记录自己的口味、厨具和火候调整。

### 4.2 商业目标

- 免费版本提供完整的本地菜谱核心闭环。
- 保证免费的本地导入流程不依赖持续推理成本。
- 未来以用户主动选择的付费 AI 辅助获得收入，具体付费形态另行确认。
- 未来通过一次性模板购买获得收入。
- 长期探索用户模板贡献奖励。

### 4.3 学习目标

- Flutter 跨平台客户端开发。
- 多 package 组件化与依赖治理。
- Riverpod、GoRouter 和跨组件通信。
- Drift、数据库迁移与本地优先设计。
- iOS 与 Android 分享、通知、后台任务等平台能力。
- 结构化 OCR、通用版面分析和未来付费 AI 的边界设计。
- Codex CLI、IDE 扩展和项目级指令的深度使用。

## 5. 目标用户

核心用户以重视生活记录和审美表达的女性用户为主，但产品视觉、文案和功能
不得排斥男性或其他用户群体。

典型特征：

- 经常在家做饭或正在学习做饭。
- 经常从多个内容平台寻找菜谱。
- 收藏内容很多，但再次查找和使用效率低。
- 希望保留个人口味和实际操作经验。
- 对手账、整理和个性化模板有兴趣。

## 6. 产品原则

- **本地优先**：核心浏览、编辑和烹饪不依赖网络。
- **用户确认**：OCR、本地解析和未来 AI 输出都是草稿，不是最终事实。
- **用户数据优先**：用户修改不得被后续处理覆盖。
- **始终可降级**：OCR、本地解析、网络和模板失败后仍可手动完成。
- **来源透明**：保留原始材料、作者和用户修改关系。
- **实用优先**：视觉表达不能损害阅读和烹饪效率。
- **数据与表现分离**：菜谱结构不依赖手账模板。
- **克制扩展**：先完成个人菜谱闭环，再扩展公共内容和创作者生态。

## 8. 功能模块

### 8.1 首页

- 主文案“今天想吃点什么？”。
- 搜索框仅搜索个人菜谱。
- 统一“创建菜谱”入口。
- 不展示推荐流、统计、最近内容或 AI 权益卡片。
- 未来可以增加“我的菜谱 / 发现菜谱”搜索域。

### 8.2 菜谱

完整需求见 `RECIPE_REQUIREMENTS.md`。

核心能力：

- 菜谱库手账缩略图。
- 搜索、筛选、排序和收藏。
- 菜谱集。
- 手账模板和阅读器。
- 手动创建、导入确认和完整编辑。
- 完整详情和份量换算。
- 逐步烹饪与烹饪记录。
- 回收站、归档和恢复。

### 8.3 导入

输入：

- 第三方应用分享的链接和文案。
- 纯文字。
- 单张或多张截图。
- 应用内粘贴。

处理：

```text
先保存原始输入
→ 保留行坐标和页序的 OCR
→ 通用版面分析
→ 本地保守解析
→ 质量校验
→ 用户确认
```

原则：

- 收到分享后立即创建本地导入记录。
- 失败记录不能自动消失。
- 不绕过第三方平台登录、验证和反爬机制。
- MVP 不直接导入视频文件。
- OCR 不可靠时允许重新选图、修改文字和手动补充。

### 8.4 未来付费 AI

- AI 辅助不属于当前 MVP 或默认导入流程。
- 未来只能由用户主动选择，并在调用前说明付费权益和上传范围。
- 具体采用订阅、次数包或组合方式另行确认。
- 付费调用失败按最终商业规则恢复权益或退还次数。
- 客户端不保存服务密钥。
- AI 只生成草稿和建议。
- 用户编辑和确认内容具有最高优先级。

### 8.5 激励广告

当前没有通过激励广告发放 AI 次数的已确认需求。若未来引入，需要作为独立产品
变更重新评审；启动、浏览、编辑、详情和烹饪过程不得展示广告。

### 8.6 模板

- 极简和手账风格共享菜谱数据和业务页面。
- 创建菜谱时选择模板，未选择时使用全局默认模板。
- 免费模板保障完整核心体验。
- 未来付费模板一次性买断。
- 长期提供受约束模板编辑器和用户上传。
- 模板贡献奖励的具体形式后续确认。

### 8.7 数据与备份

- 核心数据保存于本地数据库。
- 原始输入、结构化草稿和当前菜谱分层保存。
- 图片和模板资源使用文件存储并维护数据库引用。
- 支持本地导出和恢复。
- 云端备份与多设备同步属于后续能力。
- 用户个人菜谱默认不公开。

## 9. 产品状态模型

### 9.1 导入任务

```text
等待处理
→ 正在提取
→ 正在识别图片
→ 正在整理菜谱
→ 等待确认
→ 已保存

任意处理中状态 → 处理失败 → 重试或手动处理
```

### 9.2 菜谱

```text
待完善
可烹饪
已归档
已删除
```

### 9.3 未来付费 AI 请求

```text
待授权
→ 已预留额度
→ 请求中
→ 成功并结算

请求失败 → 退还或保持额度
```

### 9.4 烹饪会话

```text
准备中
→ 进行中
→ 已暂停
→ 已完成

进行中或暂停 → 放弃
```

## 10. 视觉方向

### 10.1 免费风格

- 极简风格。
- 手账风格。

### 10.2 手账语言

- 暖白纸张。
- 珊瑚红、黄油黄、鼠尾草绿、浅粉和雾蓝。
- 胶带、贴纸、色块、活页孔和轻微错落。
- 低对比度纸张和软木纹理。
- 手写字体只用于标题和短标签。
- 长正文使用高可读字体。

### 10.3 未来视觉商品

- 高级手账模板。
- AI 手绘食材或步骤图。
- 手绘菜谱长图。
- 高清导出和打印排版。

## 11. 非功能需求

### 11.1 离线

- 菜谱库、搜索、详情、编辑、阅读器和烹饪离线可用。
- 已下载模板离线可用。
- 网络不可用时任务可等待、重试或降级。

### 11.2 可靠性

- 导入输入先持久化再处理。
- 编辑草稿自动保存。
- 数据库写入使用事务。
- 数据迁移具有测试。
- 失败状态可恢复，不静默丢失数据。

### 11.3 性能

- 本地搜索即时反馈。
- 菜谱库滚动流畅。
- 图片和模板按显示尺寸解码并缓存。
- 长列表只构建可见内容。
- AI 和媒体处理不得阻塞 UI。

### 11.4 可访问性

- 支持系统文字缩放。
- 关键操作具备语义标签和 Tooltip。
- 装饰元素不加入语义树。
- 颜色不是状态的唯一表达方式。
- 烹饪模式使用大字号、高对比度和大点击区域。

### 11.5 隐私与安全

- 上传云端前首次明确告知。
- 用户可查看和删除原始材料。
- 客户端不保存服务 API 密钥。
- 分析事件不上传菜名、食材、步骤和个人笔记正文。
- 公开模板上线前具备审核、举报、下架和版权处理。

## 13. 基础服务地图

基础服务定义见 `services/README.md`：

- 本地数据服务。
- 媒体资源服务。
- 导入处理服务。
- AI 编排服务。
- 模板服务。
- 搜索服务。
- 权益与额度服务。
- 烹饪运行时服务。
- 备份与同步服务。

这些名称表示职责和接口边界，不要求每项建立独立 Flutter package 或后端
微服务。是否拆包取决于依赖方向、复用范围、测试成本和生命周期。
