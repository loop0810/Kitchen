## Why

当前图片导入虽然具备端侧 OCR、失败恢复和人工校对闭环，但缺少可量化质量基线，且模糊、文字过小、无关界面内容、方向未正确应用、平台元数据缺失和繁简字形误识别会共同降低结果完整度与准确性。V1 以 Android 本地图片导入为核心，需在不引入网络或 AI、也不改变繁体用户原文的前提下，对 OCR 准确率进行专项治理。

## What Changes

- 建立可重复执行的 OCR 质量样本集和分层指标，分别度量原始识别、噪声过滤、菜谱结构化、用户校对成本与端侧性能，防止仅凭个别样本判断效果。
- 在 OCR 前执行轻量图片质量诊断，识别方向异常、模糊、文字过小和正文占比不足等风险；只在可能影响识别时引导用户裁剪、旋转或替换，不强制正常图片多走一步。
- 建立保守、可版本化的条件式图片预处理流程；保留原图，预处理失败时回退原图，不对所有图片无条件应用可能损伤文字的强增强。
- 修复媒体旋转必须真实作用于 OCR 输入和结果坐标的语义，并让平台 Adapter 尽可能返回行置信度、方向和识别语言等质量元数据。
- 分离“菜谱结构完整度”和“OCR 文字质量”，避免菜名、食材、步骤非空就把含明显错字或缺行的结果视为可直接确认。
- 原始 OCR 和用户可见默认结果保留识别字形，系统不得默认把繁体转换为简体或把简体转换为繁体；内部解析可以做不改写原文的繁简等价匹配。
- 对数字、单位、菜谱词和疑似繁简混杂提供带证据的候选建议；只有用户主动采纳或主动执行可撤销的繁简转换后才修改校对正文，且不得覆盖用户编辑或确认内容。
- Android 作为 V1 质量验收主平台；iOS 保持同一领域契约并覆盖平台适配回归，但不扩大为 V1 发布前置条件。

## Capabilities

### New Capabilities

- `ocr-recognition-quality`: 定义图片质量诊断、裁剪引导、条件式预处理、平台 OCR 元数据、质量评测、原文字形保护和建议式纠错行为。

### Modified Capabilities

无。现有 `ocr-import-recovery-review` 已规定旋转、增量重识别、原始结果保留和用户编辑保护；本 change 修复其实现缺口，新质量行为由独立 capability 承担。

## Impact

- 产品与决策：更新 OCR 当前范围、MVP 质量验收、导入服务、媒体服务和决策日志，明确准确率指标与繁简字形边界。
- Import Domain/Data/UI：增加质量诊断结果、预处理修订信息、文字质量状态、纠错建议和条件式裁剪引导，并继续使用现有媒体修订号、处理代次及用户编辑保护语义。
- 平台适配：调整 Android ML Kit 与 iOS Vision 输入方向、输出坐标和可用质量元数据；Android 真机样本作为 V1 主验收入口。
- 测试资产：增加可提交的自制、脱敏或获授权图片基准，以及不提交 Git 的本地真实截图评测流程；任何样本均不得包含账号、设备标识或本机绝对路径。
- 依赖与隐私：默认离线执行，不新增服务端 API、不上传图片或 OCR 正文；若引入图像处理或繁简词库依赖，需评估包体、许可证、性能、失败回退和离线可用性。
