## Context

该 change 在共享账号会话完成后接入首个外部身份。Apple 只保证稳定 subject；邮箱与姓名可能仅首次返回，用户可使用私密中继邮箱。授权结果必须跨客户端和服务端校验 nonce 与一次性流程状态。

## Goals / Non-Goals

**Goals:**

- 完成 iOS 原生 Apple 授权和服务端可信验证。
- 以 Apple subject 自动建号或登录，不额外收集手机号。
- 正确处理隐藏邮箱、取消和凭证撤销。

**Non-Goals:**

- 不把 Apple 邮箱同步为公开个人资料。
- 不在本 change 提供 Android/Web Apple 登录。
- 不自动合并已有其他账号。

## Decisions

### 1. 客户端生成 nonce，服务端校验完整 token

客户端为每次授权生成高熵 nonce 并只向服务端提交授权结果；服务端校验 Apple 公钥签名、issuer、audience、expiry、nonce 和授权流程关联。相比信任客户端 SDK 成功回调，这能阻断伪造或跨应用 token。

### 2. provider subject 是唯一身份键

Apple subject 与应用受众范围一起映射 AuthIdentity。邮箱、姓名只在首次返回时经用户可见规则保存为可选资料，不用于查找或合并账号。

### 3. 首次认证直接进入共享 find-or-create

验证适配器只输出标准身份断言，账号创建、会话签发和幂等全部复用 `shared-auth-account-session`。这避免 Apple 模块拥有独立用户表。

### 4. 撤销事件与登录时状态共同处理

服务端提供可验证的撤销通知入口或定期状态检查边界；收到撤销后标记身份不可用于新会话。若账号还有其他身份，其他身份不受影响；账号删除遵循共享删除流程。

## Risks / Trade-offs

- [Apple 姓名只返回一次导致首次写入失败后丢失] → 身份创建与可选资料保存同事务提交，仍允许资料为空。
- [Apple 公钥轮换或网络短暂失败] → 按 key id 缓存并设有限时刷新，无法验证时失败关闭而不删除现有身份。
- [模拟器与审核环境配置不同] → 使用独立环境受众配置并增加真机、沙盒和服务端集成验证。

## Migration Plan

1. 配置 Apple capability、服务标识和非仓库秘密。
2. 实现客户端 nonce/授权与服务端验证适配器。
3. 接入共享账号自动建号和会话签发。
4. 增加取消、隐藏邮箱、重复登录、错误 audience 和撤销测试。
5. 在 iOS 显示 Apple 登录并完成真机及审核说明验证。
6. 回滚时远端关闭入口，保留既有 Apple 身份供后续恢复，不删除账号。
