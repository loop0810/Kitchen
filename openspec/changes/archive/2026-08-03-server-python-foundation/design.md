## Context

`server/` 当前存在一套尚未完成依赖解析和验证、也不包含业务 API 或用户数据的 Swift/Vapor 草案。根约束要求服务端采用模块化单体，首个工程 change 同时建立开发运行、验证和学习记录入口；本 change 将该草案替换为 Python/FastAPI 基线，但不借机确定账号 HTTP 细节。

## Goals / Non-Goals

**Goals:**

- 建立可在本地、CI 与 Linux 容器中重复运行的 Python/FastAPI 服务端基线。
- 为后续模块提供单向依赖、迁移、配置、日志和健康检查边界。
- 让秘密、生产资源和测试资源严格隔离。

**Non-Goals:**

- 不实现账号、短信、同步或部署腾讯云生产环境。
- 不提前建立所有未来业务模块或通用抽象。

## Decisions

### 1. 使用 Python 3.13 与 FastAPI 的模块化单体

首期使用单一 Python 应用，按领域、应用装配、基础设施适配器和进程入口分区。领域层不得依赖 FastAPI、SQLAlchemy 或外部 SDK；应用装配层只选择适配器，HTTP handler 不得直接创建数据库或第三方客户端。相比立即拆微服务，这更符合当前规模，也保留后续按真实边界拆分的可能。

依赖和命令由 uv 管理，`pyproject.toml` 声明直接依赖，`uv.lock` 锁定完整解析结果。生产入口使用 Uvicorn；开发、测试和生产必须使用同一锁文件，不能依赖开发者机器的全局 Python 包。

### 2. PostgreSQL 是首个持久化后端

账号、唯一身份、令牌族和后续同步需要事务与唯一约束，因此从一开始使用 PostgreSQL、SQLAlchemy 2 异步会话和 asyncpg。Alembic 是 schema 的唯一演进入口。SQLite 只可用于明确隔离的纯单元测试替身，不能让与 PostgreSQL 不同的约束语义成为唯一验证。

### 3. 配置分为非秘密配置与运行时秘密

Pydantic Settings 在进程启动阶段集中解析配置。端口、日志级别等非秘密配置可具有安全默认值；数据库口令和未来提供方密钥必须从运行环境或秘密管理设施注入。配置对象不得在日志或错误响应中输出秘密值，禁止运行到首次请求才暴露配置缺失。

### 4. 健康检查分为存活和就绪

FastAPI lifespan 负责建立和关闭共享资源。存活只反映进程可响应；就绪通过 SQLAlchemy 查询运行时 metadata 表，验证数据库连接和 migration 状态。响应不暴露连接串、主机拓扑或内部异常。相比单一 `/health` 永远返回成功，这能支持安全发布和故障摘流。

### 5. 日志使用结构化字段和显式脱敏

ASGI 中间件为每个请求生成或接受受控关联 ID，异常处理器将错误映射为稳定事件类别。日志使用标准 logging 的结构化 JSON 输出和字段白名单，禁止默认记录请求体；未来模块只能显式加入允许字段。

### 6. 测试与静态质量门槛

pytest、pytest-asyncio 和 HTTPX2 覆盖配置、ASGI 路由、中间件及 PostgreSQL 集成行为；Ruff 负责格式与 lint，mypy 对生产代码执行严格类型检查。测试环境必须显式使用名称含 `test` 的隔离数据库，migration 只在单一测试准备步骤中执行。

## Risks / Trade-offs

- [Python 动态语义可能让部分错误延迟到运行时] → 使用完整类型注解、mypy、Ruff 和边界测试，将错误前移到 CI。
- [异步数据库会话若跨请求共享会产生并发与事务问题] → 每个请求创建独立 SQLAlchemy AsyncSession，并用集成测试验证提交、回滚和连接释放。
- [多进程并发执行 migration 可能产生冲突] → 发布流程在启动应用实例前只执行一次 Alembic upgrade，应用 worker 不自动迁移。
- [Python 依赖供应链与版本漂移] → 只声明必要直接依赖，提交 `uv.lock`，并在 CI 使用锁定解析结果进行冷启动验证。
- [测试数据库增加本地门槛] → 提供明确的容器化或本地 PostgreSQL 启动说明，但不把生产部署纳入本 change。
- [过早抽象模块边界] → 只建立装配和依赖方向，不为不存在的业务创建空模块。

## Migration Plan

1. 确认 Swift/Vapor 草案不含业务数据或已发布接口后，以 Python 工程替换其清单、源码和测试，并保留无关仓库修改。
2. 使用 uv 初始化工程、锁定依赖并建立最小启动测试。
3. 接入隔离测试数据库与空迁移验证。
4. 增加健康检查、错误边界和日志脱敏测试。
5. 更新服务端文档、验证命令和学习记录。
6. Python 基线验证前可恢复尚未发布的 Swift 草案；Python 基线生效后整体回滚可停止并移除尚无业务数据的 `server/` 工程，不得影响现有 Flutter 客户端。
