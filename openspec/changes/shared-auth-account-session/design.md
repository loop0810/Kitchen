## Context

客户端已有个性化配置远端网关，但没有正式会话、通用 HTTP 契约或服务端实现。Apple、手机号和微信若分别创建账号模型，会使自动建号、身份冲突和删除语义无法收敛；设备本地菜谱又必须在未登录与服务端故障时继续可用。

## Goals / Non-Goals

**Goals:**

- 用稳定内部账号承载多个已验证身份。
- 建立可撤销、可检测重放的按设备会话。
- 定义首个正式鉴权 API、错误、幂等和删除边界。

**Non-Goals:**

- 不实现任何具体提供方凭证验证。
- 不上传或同步设备本地菜谱。
- 不实现两个已存在账号的自动合并。

## Decisions

### 1. User 与 AuthIdentity 分离

`User` 只使用服务端生成的不透明 `userId`；`AuthIdentity` 使用 `(provider, providerSubject, issuer/audience scope)` 唯一约束指向账号。手机号、Apple 和微信都是身份记录而不是用户主键，这允许更换、绑定和撤销提供方而不改变业务 ID。

### 2. 首次登录在事务内 find-or-create

提供方适配器先产生标准化且已验证的身份断言，Auth 模块在单一事务中查找或创建账号与身份。数据库唯一约束和幂等键共同处理并发重试，而不是依赖客户端“只提交一次”。

### 3. 不提供隐式账号合并

绑定只允许“当前已认证账号 + 新近重新认证且未占用身份”。若身份已属于另一账号，返回稳定冲突；未来账号合并必须独立设计数据选择、审计和回滚。

### 4. 短期 access token 与旋转 refresh token

Access token 只承载最小 subject、session 和时效声明；Refresh token 使用高熵不透明值，服务端只保存摘要和 token family。每次刷新轮换，旧值重放撤销该族。相比长期不可撤销 JWT，这支持设备退出和泄露响应。

### 5. 客户端安全存储与业务缓存分离

刷新凭证只进入 Keychain/Keystore 类安全存储，不进入 Drift、普通偏好、系统应用数据备份或日志。客户端通过单一 SessionRepository 输出匿名、认证中、已登录和失效状态，Feature 不直接读取令牌。

### 6. 账号删除采用可审计状态机

删除请求先近期重新认证，再撤销全部会话并进入删除状态；服务端数据按权威保留期和关联 contract 清理。本地资料库的保留或清除由客户端独立确认，服务端不得远程删除本机菜谱。

## Risks / Trade-offs

- [刷新令牌被复制后发生竞争] → 轮换、token family 重放检测和设备会话列表共同处理。
- [提供方身份声明范围配置错误造成串号] → 唯一键包含 provider 与 issuer/audience scope，并为生产、测试使用不同配置。
- [账号删除与异步数据清理结果不一致] → 使用删除状态和可重试清理任务，API 明确返回处理中而非提前宣称完成。
- [认证服务故障影响启动] → 会话恢复异步进行，本地核心功能不依赖其成功。

## Migration Plan

1. 先完成 `server-python-foundation`。
2. 新增认证契约和账号、身份、会话迁移，不接入外部登录入口。
3. 实现会话签发、刷新、撤销、错误 envelope 和幂等测试。
4. 客户端接入安全存储与匿名/已登录状态，但保持默认匿名可用。
5. 接入账号删除与会话管理，再开放具体登录方式。
6. 回滚登录入口时保留账号数据和迁移，禁用新会话签发并让本地功能继续工作。
