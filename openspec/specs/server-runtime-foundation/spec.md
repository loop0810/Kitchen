# server-runtime-foundation Specification

## Purpose

为后续账号、同步和其他云端能力提供可重复启动、可安全配置、可迁移并可诊断的服务端运行基线，同时保持业务模块与基础设施解耦。

## Requirements

### Requirement: 服务端具有可验证的启动与健康状态
系统 SHALL 在必需配置和依赖可用时启动 HTTP 服务并提供不泄露敏感信息的存活与就绪状态；必需配置缺失或数据库不可用时 MUST 拒绝进入就绪状态。

#### Scenario: 依赖完整时启动
- **WHEN** 服务端以有效配置连接到测试数据库并完成启动
- **THEN** 存活检查成功，且就绪检查确认数据库可用

#### Scenario: 必需配置缺失
- **WHEN** 服务端启动时缺少数据库连接或其他标记为必需的配置
- **THEN** 服务端以明确的非零结果失败，且日志不输出密钥内容

### Requirement: 数据库结构通过受控迁移演进
系统 SHALL 使用有序、可审计的迁移创建和升级持久化结构，并 MUST 能在空数据库和已应用旧迁移的数据库上验证目标版本。

#### Scenario: 空数据库初始化
- **WHEN** 对空测试数据库执行迁移
- **THEN** 所有迁移按顺序成功应用且再次执行不会重复创建结构

### Requirement: 运行日志保护敏感数据
系统 SHALL 输出带请求关联标识和稳定事件名称的结构化日志，并 MUST NOT 记录访问令牌、刷新令牌、第三方密钥、菜谱正文、图片内容或完整手机号。

#### Scenario: 请求处理失败
- **WHEN** 任意 API 请求产生可预期或非预期错误
- **THEN** 日志包含关联标识和安全错误类别，但不包含请求中的认证秘密

### Requirement: 运行配置按环境隔离
系统 SHALL 允许开发、测试和生产使用独立配置，生产秘密 MUST 从运行环境或秘密管理设施注入，不得存在于仓库或构建产物中。

#### Scenario: 运行自动化测试
- **WHEN** 测试套件启动服务端
- **THEN** 服务端只使用隔离测试配置和测试数据库，不访问生产资源
